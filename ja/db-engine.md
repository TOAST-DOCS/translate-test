## Database > RDS for PostgreSQL > DBエンジン { #database-rds-for-postgresql-db-engine }

<a id="db-engine"></a>
## DBエンジン { #db-engine }
PostgreSQLのバージョン番号は `X.Y` 形式で構成されます。NHN CloudのRDS for PostgreSQLで `X` はメジャーバージョン、 `Y` はマイナーバージョンを表します。

<a id="db-engine-version-provided-by-rds"></a>
### RDSが提供するDBエンジンのバージョン { #db-engine-version-provided-by-rds }

下記のバージョンを使用できます。


| バージョン            | 備考 |
|---------------------|-------------------------------|
| <strong>17</strong> |                               |
| PostgreSQL 17.10    |                               |
| PostgreSQL 17.6     |                               |
| PostgreSQL 17.4     |                               |
| PostgreSQL 17.2     | 新規作成またはリードレプリカを追加できません。 |
| <strong>14</strong> |                               |
| PostgreSQL 14.23    |                               |
| PostgreSQL 14.19    |                               |
| PostgreSQL 14.17    |                               |
| PostgreSQL 14.15    | 新規作成またはリードレプリカを追加できません。 |
| PostgreSQL 14.6     | 新規作成またはリードレプリカを追加できません。 |

!!! warning "注意"
    PostgreSQL 14.6, 14.15, 17.2バージョンは最新バージョンへのアップグレードを[推奨](https://www.postgresql.org/support/security/CVE-2025-1094/)します。

<a id="perform-version-upgrades"></a>
### バージョンアップグレードを実行する { #perform-version-upgrades }

バージョンアップグレードは順次行われ、メジャーバージョンアップグレードとマイナーバージョンアップグレードのそれぞれの特性によって異なる順序で行われることがあります。

バージョンアップグレードを行う前に、データ損失防止のため、バックアップを行うことを推奨します。

<a id="perform-version-upgrades-major-version-upgrade"></a>
#### メジャーバージョンアップグレード

メジャーバージョンアップグレードは、バージョン番号の最初の桁を変更することを意味します。例えば、14.6から17.2にアップグレードすることがメジャーバージョンアップグレードです。

RDS for PostgreSQLでは、メジャーバージョンアップグレードはマスターでのみ実行可能で、実行した場合、DBインスタンスグループ内のすべてのDBインスタンスに対してバージョンアップグレードを行います。

<a id="perform-version-upgrades-major-version-upgrade-order"></a>
#### メジャーバージョンアップグレードの順序

マスターDBインスタンスを変更してメジャーバージョンアップグレードを実行できます。
実行順序は次のとおりです。

- マスターDBインスタンスでバージョンアップグレードの事前点検を実施します。
    - 事前点検の結果、問題がなければバージョンアップグレードを実施します。
    - 事前点検の結果はログファイル形式で提供され、DBインスタンス詳細の**[ログ]**タブで`pg_upgrade.log`ファイルを確認できます。
- DBインスタンスグループ内にマスターのみが存在する場合、マスターDBインスタンスのバージョンアップグレードを実施します。
    - バージョンアップグレード中はダウンタイムが発生します。
    - 失敗した場合、復旧作業が試みられることがあり、復旧に成功するとバージョンアップグレード前の状態に戻ります。
    - 復旧作業にも失敗した場合、再構築で復旧を試みることができます。
- マスター以外の複製関係にあるDBインスタンス（予備マスターを含む）の中からDBインスタンスを1つ選定して進めます。
    - 選定したDBインスタンスのバージョンアップグレードを実施します。
        - 予備マスターがある場合、リードレプリカより優先してバージョンアップグレードを実施します。
        - バージョンアップグレードに失敗した場合、他のDBインスタンスに対してはバージョンアップグレードを進めず、失敗したDBインスタンスは再構築作業で復旧を試みることができます。
    - アップグレードが完了したDBインスタンスの種類をマスターに変更し、グループ内の残りのDBインスタンスをアップグレードして複製関係をリセットします。
        - 接続アドレスは変更されないため、既存の接続アドレスで接続できます。
        - バージョンアップグレード中は、リードレプリカにダウンタイムが発生します。
        - バージョンアップグレード中に失敗した場合、複製が中断した状態で維持され、再構築作業で復旧を試みることができます。

!!! warning "注意"
    マスター以外の複製関係のDBインスタンスをアップグレードする段階では、マスターの書き込み負荷はブロックされ、読み取り負荷のみ処理できます。
    DBインスタンスグループ内で、バージョンアップグレードが成功したDBインスタンスと失敗したDBインスタンスが混在する場合があります。失敗したDBインスタンスは複製関係が中断され、再構築操作で復旧を試みることができます。

<a id="perform-version-upgrades-miner-version-upgrade"></a>
#### マイナーバージョンアップグレード

マイナーバージョンアップグレードは、バージョン番号の2桁目を変更することを意味します。例えば、14.6から14.15にアップグレードすることがマイナーバージョンアップグレードです。

RDS for PostgreSQLでは、マイナーバージョンアップグレードはマスターだけでなく、リードレプリカでも実行可能で、実行した場合、対象のDBインスタンスのバージョンがアップグレードされます。高可用性構成が完了したマスターは、予備マスターも一緒にアップグレードします。

<a id="perform-version-upgrades-minor-version-upgrade-order"></a>
#### マイナーバージョンアップグレード順序

- マスターに対してバージョンアップグレードを試みる際、予備マスターが存在する場合、一緒にバージョンをアップグレードします。
    - マスター単独でバージョンアップグレードが進行される場合、ダウンタイムが発生します。
    - 予備マスターと一緒にバージョンアップグレードが進行される場合、プロセス中にフェイルオーバーを利用した再起動が伴い、瞬断が発生する可能性があります。
- リードレプリカのバージョンをアップグレードする場合、当該DBインスタンス単独でバージョンをアップグレードします。
    - バージョンアップグレードの進行時にダウンタイムが存在します。
    - バージョンアップグレードの進行中に失敗した場合、復旧作業が試行されることがあり、成功した場合、バージョンアップグレードの進行前の状態に復旧されます。
    - バージョンアップグレードに失敗した後、復旧作業に失敗した場合、再構築を通じて復旧を試みることができます。
