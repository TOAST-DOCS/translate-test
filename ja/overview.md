## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは仮想のCPU、メモリ、ルートブロックストレージで構成された仮想サーバーです。このサーバーにお客様のサービスやアプリケーションをインストールし、NHN Cloudが提供するさまざまなサービスを組み合わせて使用します。

<a id="components"></a>

## インスタンスの構成要素 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーションシステムを含む仮想ディスク
- **タイプ**(flavor): インスタンスの仮想ハードウェア性能
- **アベイラビリティゾーン**(AZ, availability zone): インスタンスが作成される物理的な場所
- **キーペア**(key-pair): インスタンスへの接続手段として使用されるキー
- **セキュリティグループ**(security groups): インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク

この情報に応じて、インスタンスの属性と使用方法が変わります。この情報のうち、イメージとアベイラビリティゾーンを除く設定はインスタンスの作成後も変更できますが、一部のインスタンスタイプ(flavor)はインスタンスの作成後に変更することはできません。インスタンスタイプの変更についての詳細は、[コンソール使用ガイドのインスタンスタイプの変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ { #image }

イメージはオペレーションシステムを含む仮想ディスクです。NHN CloudはDebian、Ubuntu、Rocky、Windowsをサポートしています。

すべてのイメージは、インスタンスの仮想ハードウェアで最適に動作するよう設定されており、NHN Cloudのセキュリティ検証を経ているため、安全に使用できます。イメージの詳細については、[イメージ概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### Instance Flavor { #flavor }

NHN Cloudはお客様の用途に合わせたさまざまなインスタンスタイプを提供しています。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。既に作成されたインスタンスのタイプもWebコンソールで簡単に変更できます。

| タイプ | 説明 |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPUとメモリをバランスよく設定したタイプです。サービスやアプリケーションのパフォーマンス要件が明確でない場合に使用します。 |
| c2 | CPUの性能を高く設定したインスタンスタイプです。高い演算性能が必要なWebアプリケーションサーバーや分析システムに使用します。 |
| r2 | 他のリソースに比べてメモリの使用量が多い場合に使用できます。通常、メモリデータベースやキャッシュサーバーに使用します。 |
| t2 | コストが低いインスタンスです。作業負荷が高くないサーバーに使用します。 |
| u2 | 最もコストが低いインスタンスです。作業負荷が高くないサーバーで使用します。<br>ローカルブロックストレージを使用するため、相対的に他のインスタンスより安定性が落ちますが、低価格で利用できます。<br>このタイプのインスタンスはI/Oパフォーマンスを保証しません。 |
| x1 | ハイスペックのCPUとメモリをサポートするタイプです。高性能が必要なサービスやアプリケーションに使用します。 |

<a id="availability-zone"></a>
### Availability Zone { #availability-zone }

NHN Cloudは物理ハードウェアの問題により発生する障害に備えるため、システム全体を複数のアベイラビリティゾーンに分割しています。このアベイラビリティゾーンごとに、ストレージシステム、ネットワークスイッチ、ラック、電源装置がすべて別個に構成されています。あるアベイラビリティゾーン内で発生する障害は他のアベイラビリティゾーンに影響を与えないため、サービス全体の可用性が向上します。インスタンスを複数のアベイラビリティゾーンに分散して構築すると、サービスの可用性をさらに高めることができます。

異なるアベイラビリティゾーン間には次のような特性があります。

- 複数のアベイラビリティゾーンに分散して作成されたインスタンス間でネットワーク通信が可能であり、この際に発生するネットワーク使用料金は課金されません。
- 同じアベイラビリティゾーンに作成されたインスタンス間ではブロックストレージを共有できますが、異なるアベイラビリティゾーン間ではブロックストレージを共有することはできません。
- 異なるアベイラビリティゾーン間でFloating IPを共有できます。あるアベイラビリティゾーンに障害が発生した場合でも、迅速に別のアベイラビリティゾーンへFloating IPを移動して、障害時間を最小化できます。

<a id="key-pair"></a>
### Key-pair { #key-pair }

キーペアは公開鍵基盤([PKI](https://ko.wikipedia.org/wiki/%EA%B3%B5%EA%B0%9C_%ED%82%A4_%EA%B8%B0%EB%B0%98_%EA%B5%AC%EC%A1%B0), public key infrastructure)に基づいたSSH公開鍵・秘密鍵のペアです。NHN Cloudで作成したインスタンスに接続するには、セキュリティ上脆弱なキーボード入力によるID/パスワード認証の代わりに、キーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードし、インスタンスに送信して接続認証を受けた後、安全にインスタンスに接続できます。キーペアを使用したインスタンスへの接続方法については、[インスタンスの接続方法](#how-to-access-instances)を参照してください。

キーペアは、インスタンスの作成時にNHN Cloudコンソールで新規作成することも、お客様が独自に作成したキーペアを登録して使用することもできます。キーペアの登録方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密鍵をダウンロードすることになります。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクやUSBドライブなどに大切に保管してください。秘密鍵が外部に漏洩すると、誰でも漏洩した秘密鍵でそのインスタンスにアクセスできるため、慎重に管理する必要があります。

> [参考]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除しても削除されずに維持されます。

<a id="security-groups"></a>
### Security Groups { #security-groups }

セキュリティグループは、インスタンスに届くネットワークトラフィックを決定する仮想ファイアウォールです。セキュリティグループの詳細については、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

> [参考]
> デフォルトのセキュリティグループは、外部からのインバウンド(in-bound)ネットワークトラフィックをすべて無視するように設定されています。SSHでインスタンスに接続する際は、インスタンスが属するセキュリティグループにSSHポートを開放するよう設定してから、インスタンスに接続します。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPCで定義されたネットワークのうち、少なくとも1つ以上に接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

<a id="pricing"></a>

## 課金 { #pricing }

インスタンスの課金方式は次のとおりです。

* インスタンスは作成した瞬間から課金されます。
* インスタンスのルートブロックストレージは、インスタンスとは別にブロックストレージの課金基準で課金されます。
* インスタンスが停止すると、90日間はWebサイト料金基準で90%割引の金額が適用されます。停止状態が90日を超えると、停止状態を維持したまま通常料金に切り替わります。
* 終了したインスタンスは課金されません。

課金の詳細については、サービスごとの[料金ページ](https://$[ price_dom[f] ]$/kr/service/compute/instance#price)を参照してください。

<a id="how-to-access-instances"></a>

## インスタンスの接続方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linuxインスタンスの接続方法 { #how-to-access-linux-instances }

LinuxインスタンスへのアクセスにはSSHクライアントを使用します。インスタンスのセキュリティグループでSSHアクセスポート（デフォルト22）が開いていない場合、接続できません。SSHアクセスを許可する方法については、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。インスタンスにFloating IPが割り当てられていない場合、NHN Cloud外部からは接続できません。Floating IPを割り当てる方法については、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

<a id="how-to-access-linux-instances-from-mac-or-linux-using-an-ssh-client"></a>
#### MacまたはLinuxのSSHクライアントでLinuxインスタンスに接続する方法

MacやLinuxには通常、SSHクライアントがデフォルトでインストールされています。SSHクライアントから次のようにキーペアの秘密鍵を使用して接続します。

Ubuntuインスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスのIP>

Debianインスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスのIP>

Rockyインスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスのIP>

<a id="how-to-access-linux-instances-from-windows-using-putty-ssh-client"></a>
#### WindowsでPuTTY SSHクライアントを使用してLinuxインスタンスに接続する方法

PuTTY SSHクライアントは、WindowsでよくSSHクライアントとして使用されるプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html)または韓国語パッチが適用された[iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i)をインストールします。

WindowsでPuTTY SSHクライアントを使用してLinuxインスタンスに接続するには、3つのステップが必要です。

* キーペアの秘密鍵をPuTTY用秘密鍵に変換
* PuTTY用秘密鍵をPuTTYに登録
* PuTTYでインスタンスに接続

##### 1. キーペアの秘密鍵をPuTTY用秘密鍵に変換

PuTTYでは、キーペアの秘密鍵をPuTTYの秘密鍵形式に変換して使用する必要があります。キーの変換は、PuTTYと一緒にインストールされるputtygenを使用します。

![イメージ1](http://static.toastoven.net/prod_instance/putty001.png)

**[PuTTY Key Generator]** ダイアログボックスの一番下の**[パラメータ]** で**[生成するキーの種類]** を**[RSA]** に選択し、**[生成するキーのビット数]** はデフォルト値の「2048」ビットを入力します。**[操作]** の**[秘密鍵ファイルの読み込み]** の横にある**[読み込み]** ボタンをクリックし、キーペアの秘密鍵ファイルを読み込みます。

![イメージ2](http://static.toastoven.net/prod_instance/putty002.png)

**[操作]** の**[生成されたキーの保存]** の横にある**[秘密鍵の保存]** ボタンをクリックし、PuTTY用に変換されたキーペアの秘密鍵を保存します。**[キーパスフレーズ]** を空白のままにして秘密鍵を保存すると、**[パスフレーズで保護せずにこのキーを保存しますか?]** というメッセージが表示されます。変換された秘密鍵をより安全に保存するには、パスフレーズを設定して保存します。

> [注意]
インスタンスに自動的にログインするように設定するには、パスフレーズを使用しないでください。パスフレーズを使用すると、ログイン時に秘密鍵のパスワードを直接入力する必要があります。

##### 2. PuTTY用秘密鍵をPuTTYに登録

このように作成されたPuTTY用秘密鍵は、2つの方法で登録して使用できます。

* PuTTYで認証秘密鍵ファイルを登録して使用する方法
* pageant（PuTTY認証エージェント）に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTYで認証秘密鍵ファイルを登録して使用する方法**


PuTTYを起動し、左側の**[カテゴリ]** で **[接続] > [SSH] > [Auth]** を選択します。右側の**[認証パラメータ]** の下の**[認証秘密鍵ファイル]** にPuTTY用秘密鍵を登録します。

![イメージ3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録したら、接続情報を保存しておくと、毎回秘密鍵ファイルを再登録する必要がありません。接続情報の保存方法については、下の接続方法を参照してください。


**B. pageant（PuTTY認証エージェント）に認証秘密鍵ファイルを登録して使用する方法**


PuTTYと一緒にインストールされるpageantを起動すると、下の図のようにWindowsトレイにアイコンが表示されます。pageantアイコンを右クリックし、**[キーの追加]** メニューをクリックしてPuTTY用秘密鍵を追加します。

![イメージ4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**[キーの表示]** を選択します。キーが正常に追加されると、下の図のように追加されたキーが表示されます。

![イメージ5](http://static.toastoven.net/prod_instance/putty008.png)

pageantは一度起動すると、Windowsトレイに常駐して実行されるため、インスタンスに接続するたびに再起動する必要はありません。ただし、Windowsを再起動した場合は再度起動する必要があります。

##### 3. PuTTYでインスタンスに接続

PuTTY用に変換された秘密鍵が正常に登録されている場合、PuTTYを起動します。

![イメージ6](http://static.toastoven.net/prod_instance/putty009.png)

基本接続情報の**[ホスト名]** は次のように使用します。

Ubuntu

	ubuntu@<インスタンスのIP>

Debian

	debian@<インスタンスのIP>

Rocky

	rocky@<インスタンスのIP>

**[ポート]** はSSHのデフォルトポートである22、**[接続形式]** は**[SSH]** に指定します。

すべての情報が正確であれば、セッションを保存します。**[読み込み、保存、保存済みセッションの削除]** の「保存済みセッション」フィールドに保存するセッション名を入力し、**[保存]** ボタンをクリックしてセッションを保存します。セッションを保存しないと、2-Aで登録した秘密鍵の設定も維持されません。

**[開く]** をクリックすると、インスタンスに接続します。

<a id="how-to-access-windows-instances"></a>
### Windowsインスタンスの接続方法 { #how-to-access-windows-instances }

Windowsサーバーに接続するには、NHN CloudコンソールでWindowsインスタンスを選択します。インスタンス詳細画面の**[接続情報]** タブで**[パスワード確認]** ボタンをクリックし、Windowsサーバーに設定されたパスワードを確認します。

**[パスワード確認]** で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザでパスワードを復号化する作業にのみ使用されます。

**[パスワード確認]** の横の**[接続]** ボタンをクリックし、リモートデスクトップ接続設定が保存された.rdpファイルをダウンロードして実行すると、Windowsサーバーに接続します。WindowsサーバーのIDは`Administrator`で、パスワードはNHN Cloudコンソールで確認したパスワードを使用します。

<a id="how-to-connect-serial-console"></a>
### シリアルコンソール接続方法 { #how-to-connect-serial-console }

ブート失敗、ネットワーク構成の問題など、SSHクライアントを使用できない状況でシリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には次の制約があります。

* インスタンスごとに1つのシリアルコンソール接続のみ可能で、複数接続を試みた場合、正常に接続できない場合があります。
* 個人がアップロードしたイメージで作成したインスタンスとプライベートイメージで作成したインスタンスは、シリアルコンソール接続を保証しません。
* シリアルコンソール接続は最大10分間接続可能です。
* Windowsインスタンスはシリアルコンソール機能をサポートしていません。
* 2026年1月27日のリリース以前に作成したインスタンスは、**[インスタンスの停止]** の後に**[インスタンスの起動]** が必要です。**[インスタンスの再起動]** 機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスに接続してブート方法を変更した場合、ブートに失敗する可能性があり、それによる結果はユーザーの責任となります。
> 通常の状況では、SSHクライアント接続の使用をお勧めします。

<a id="how-to-connect-serial-console-change-grub-bootloader-settings"></a>
#### GRUBブートローダー設定の変更

2024年11月26日のリリース以前に作成したインスタンスでブートローダーを操作するには、GRUB設定が必要です。

GRUB設定ファイルを編集します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
```

変更した設定を適用します。OSによってGRUB設定の適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
