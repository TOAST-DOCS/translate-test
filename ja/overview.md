<a id="compute-instance-overview"></a>
## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは仮想のCPU、メモリ、ルートブロックストレージで構成された仮想サーバーです。このサーバーにお客様のサービスやアプリケーションをインストールし、NHN Cloudが提供するさまざまなサービスを組み合わせて使用します。

<a id="components"></a>
## インスタンスの構成要素 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーションシステムを格納した仮想ディスク
- **タイプ**(flavor): インスタンスの仮想ハードウェア性能
- **アベイラビリティゾーン**(AZ, availability zone): インスタンスが作成される物理的な場所
- **キーペア**(key-pair): インスタンスへの接続に使用するキー
- **セキュリティグループ**(security groups): インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク

この情報に応じてインスタンスの属性と使用方法が変わります。この情報のうち、イメージとアベイラビリティゾーンを除く設定はインスタンス作成後も変更できますが、一部のインスタンスタイプ(flavor)はインスタンス作成後に変更することはできません。インスタンスタイプの変更の詳細については、[コンソール使用ガイドのインスタンスタイプ変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ { #image }

イメージはオペレーションシステムを格納した仮想ディスクです。NHN CloudはDebian、Ubuntu、RockyおよびWindowsをサポートしています。

すべてのイメージはインスタンスの仮想ハードウェアで最適に実行されるよう設定されており、NHN Cloudのセキュリティ検証を経ているため、安全に使用できます。イメージの詳細については、[イメージ概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### Instance flavor { #flavor }

NHN Cloudはお客様の用途に合わせたさまざまなインスタンスタイプを提供します。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。既に作成されたインスタンスのタイプもウェブコンソールで簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPUとメモリをバランスよく設定したタイプです。サービスやアプリケーションのパフォーマンス要件が明確でない場合に使用します。 |
| c2 | CPUの性能を高く設定したインスタンスタイプです。高い演算性能が必要なウェブアプリケーションサーバーや分析システムに使用します。 |
| r2 | 他のリソースと比較してメモリの使用量が多い場合に使用できます。通常はメモリデータベースやキャッシュサーバーに使用します。 |
| t2 | コストが低廉なインスタンスです。作業負荷が高くないサーバーに使用します。 |
| u2 | 最もコストが低廉なインスタンスです。作業負荷が高くないサーバーで使用します。<br>ローカルブロックストレージを使用するため、他のインスタンスと比較して安定性が落ちますが、低価格で利用できます。<br>このタイプのインスタンスはI/O性能を保証しません。 |
| x1 | ハイスペックのCPUとメモリをサポートするタイプです。高い性能が必要なサービスやアプリケーションに使用します。 |

<a id="availability-zone"></a>
### Availability zone { #availability-zone }

NHN Cloudは物理ハードウェアの問題による障害に備えるため、システム全体を複数のアベイラビリティゾーンに分割しています。このアベイラビリティゾーンごとに、ストレージシステム、ネットワークスイッチ、ラック、電源装置がそれぞれ独立して構成されています。あるアベイラビリティゾーン内で発生した障害は他のアベイラビリティゾーンに影響しないため、サービス全体の可用性が向上します。インスタンスを複数のアベイラビリティゾーンに分散して構築すると、サービスの可用性をさらに高めることができます。

異なるアベイラビリティゾーン間には次のような特性があります。

- 複数のアベイラビリティゾーンに分散して作成されたインスタンス間でネットワーク通信が可能であり、この際に発生するネットワーク使用料金は課金されません。
- 同じアベイラビリティゾーンに作成されたインスタンス間ではブロックストレージを共有できますが、異なるアベイラビリティゾーン間ではブロックストレージを共有することはできません。
- 異なるアベイラビリティゾーン間でFloating IPを共有できます。あるアベイラビリティゾーンで障害が発生した場合でも、迅速に別のアベイラビリティゾーンへFloating IPを移動することで、障害時間を最小化できます。

<a id="key-pair"></a>
### Key-pair { #key-pair }

キーペアは公開鍵基盤([PKI](https://ko.wikipedia.org/wiki/%EA%B3%B5%EA%B0%9C_%ED%82%A4_%EA%B8%B0%EB%B0%98_%EA%B5%AC%EC%A1%B0), public key infrastructure)に基づくSSH公開鍵・秘密鍵のペアです。NHN Cloudで作成したインスタンスに接続するには、セキュリティ上脆弱なキーボード入力方式のID/パスワード認証の代わりにキーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードし、インスタンスへ送信して接続認証を受けた後、安全にインスタンスに接続できます。キーペアを使用したインスタンスの接続方法については、[インスタンスの接続方法](#how-to-access-instances)を参照してください。

キーペアはインスタンス作成時にNHN Cloudコンソールで新規作成することも、お客様が自作したキーペアを登録して使用することもできます。キーペアの登録方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密鍵をダウンロードすることになります。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクやUSBドライブなどに大切に保管してください。秘密鍵が外部に漏洩した場合、誰でも漏洩した秘密鍵でそのインスタンスにアクセスできるため、慎重に管理する必要があります。

> [参考]
> キーペアはユーザーアカウントに割り当てられたリソースであるため、プロジェクトを削除しても削除されずに維持されます。

<a id="security-groups"></a>
### Security groups { #security-groups }

セキュリティグループはインスタンスに転送されるネットワークトラフィックを制御する仮想ファイアウォールです。セキュリティグループの詳細については、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

> [参考]
> デフォルトのセキュリティグループは外部からの受信(in-bound)ネットワークトラフィックをすべて無視するよう設定されています。SSHでインスタンスに接続する際は、インスタンスが属するセキュリティグループでSSHポートを開くよう設定してからインスタンスに接続します。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPCで定義されたネットワークのうち少なくとも1つに接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

<a id="pricing"></a>
## 課金 { #pricing }

インスタンスの課金方式は次のとおりです。

* インスタンスは作成した瞬間から課金されます。
* インスタンスのルートブロックストレージは、インスタンスとは別にブロックストレージの課金基準で課金されます。
* インスタンスが停止すると、90日間はWebサイト料金基準で90%割引した金額が適用されます。停止状態が90日を超えると、停止状態を維持しながら通常料金に切り替わります。
* 終了したインスタンスは課金されません。

課金の詳細については、サービスごとの[料金ページ](https://$[ price_dom[f] ]$/kr/service/compute/instance#price)を参照してください。

<a id="how-to-access-instances"></a>
## インスタンス接続方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linuxインスタンス接続方法 { #how-to-access-linux-instances }

Linuxインスタンスに接続する際は、SSHクライアントを使用します。インスタンスのセキュリティグループにSSHアクセスポート（デフォルト22）が開いていない場合は、接続できません。SSHアクセスを許可する方法については、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。インスタンスにFloating IPが割り当てられていない場合は、NHN Cloud外部から接続することはできません。Floating IPを割り当てる方法については、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

<a id="how-to-access-linux-instances-from-mac-or-linux-using-an-ssh-client"></a>
#### MacまたはLinuxのSSHクライアントを使用してLinuxインスタンスに接続する方法

MacやLinuxには通常、SSHクライアントがデフォルトでインストールされています。SSHクライアントで以下のようにキーペアの秘密鍵を使用して接続します。

Ubuntuインスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスのIP>

Debianインスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスのIP>

Rockyインスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスのIP>

<a id="how-to-access-linux-instances-from-windows-using-putty-ssh-client"></a>
#### WindowsでPuTTY SSHクライアントを使用してLinuxインスタンスに接続する方法

PuTTY SSHクライアントは、Windowsで広く使用されているSSHクライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html)または韓国語パッチが適用された[iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i)をインストールします。

WindowsでPuTTY SSHクライアントを使用してLinuxインスタンスに接続するには、3つの手順が必要です。

* キーペアの秘密鍵をPuTTY用の秘密鍵に変換
* PuTTY用の秘密鍵をPuTTYに登録
* PuTTYでインスタンスに接続

##### 1. キーペアの秘密鍵をPuTTY用の秘密鍵に変換

PuTTYでは、キーペアの秘密鍵をPuTTYの秘密鍵形式に変換して使用する必要があります。キーの変換は、PuTTYとともにインストールされるputtygenを使用します。

![イメージ1](http://static.toastoven.net/prod_instance/putty001.png)

**[PuTTY Key生成器]** ダイアログボックスの一番下の **[パラメータ]** で **[生成するキーの形式]** を **RSA** に選択し、**[生成するキーのビット数]** にはデフォルト値の「2048」ビットを入力します。**[操作]** の下の **[秘密鍵ファイルの読み込み]** の横にある **[読み込み]** ボタンをクリックし、キーペアの秘密鍵ファイルを読み込みます。

![イメージ2](http://static.toastoven.net/prod_instance/putty002.png)

**[操作]** の下の **[生成されたキーの保存]** の横にある **[秘密鍵の保存]** ボタンをクリックして、PuTTY用に変換されたキーペアの秘密鍵を保存します。**[キーパスフレーズ]** を空欄のまま秘密鍵を保存すると、**[パスフレーズで保護せずにこのキーを保存しますか？]** というメッセージが表示されます。変換された秘密鍵をより安全に保存するには、パスフレーズを設定して保存します。

> [注意]
インスタンスへの自動ログインを設定するには、パスフレーズを使用しないでください。パスフレーズを使用すると、ログイン時に秘密鍵のパスワードを直接入力する必要があります。

##### 2. PuTTY用の秘密鍵をPuTTYに登録

このように作成したPuTTY用の秘密鍵は、2つの方法で登録して使用できます。

* PuTTYで認証秘密鍵ファイルを登録して使用する方法
* pageant（PuTTY認証エージェント）に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTYで認証秘密鍵ファイルを登録して使用する方法**


PuTTYを起動し、左側の **[カテゴリ]** で **[接続] > [SSH] > [Auth]** を選択します。右側の **[認証パラメータ]** の下の **[認証秘密鍵ファイル]** にPuTTY用の秘密鍵を登録します。

![イメージ3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、接続情報を保存しておけば、毎回秘密鍵ファイルを再登録する必要がありません。接続情報を保存する方法については、下記の接続方法を参照してください。


**B. pageant（PuTTY認証エージェント）に認証秘密鍵ファイルを登録して使用する方法**


PuTTYとともにインストールされるpageantを起動すると、下の図のようにWindowsトレイにアイコンが表示されます。pageantアイコンを右クリックし、**[キーの追加]** メニューをクリックしてPuTTY用の秘密鍵を追加します。

![イメージ4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**[キーの表示]** を選択します。キーが正しく追加された場合、下の図のように追加されたキーが表示されます。

![イメージ5](http://static.toastoven.net/prod_instance/putty008.png)

pageantは一度起動すると、Windowsトレイに常駐して実行され続けるため、インスタンスに接続するたびに再起動する必要がありません。ただし、Windowsを再起動した場合は、再度起動する必要があります。

##### 3. PuTTYでインスタンスに接続

PuTTY用に変換された秘密鍵が正しく登録されていれば、PuTTYを起動します。

![イメージ6](http://static.toastoven.net/prod_instance/putty009.png)

基本接続情報の **[ホスト名]** は次のように使用します。

Ubuntu

	ubuntu@<インスタンスのIP>

Debian

	debian@<インスタンスのIP>

Rocky

	rocky@<インスタンスのIP>

**[ポート]** にはSSHのデフォルトポートである22、**[接続形式]** には **SSH** を指定します。

すべての情報が正確であれば、セッションを保存します。**[読み込み、保存、保存済みセッションの削除]** で、保存済みセッションの下のフィールドに保存するセッション名を入力し、**[保存]** ボタンをクリックしてセッションを保存します。セッションを保存しない場合、2-Aで登録した秘密鍵の設定も維持されません。

**[開く]** をクリックすると、インスタンスに接続します。

<a id="how-to-access-windows-instances"></a>
### Windowsインスタンス接続方法 { #how-to-access-windows-instances }

Windowsサーバーに接続するには、NHN Cloudコンソールで接続するWindowsインスタンスを選択します。インスタンスの詳細画面の **[接続情報]** タブで **[パスワード確認]** ボタンをクリックして、Windowsサーバーに設定されたパスワードを確認します。

**[パスワード確認]** で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザでパスワードを復号する処理にのみ使用されます。

**[パスワード確認]** の横にある **[接続]** ボタンをクリックして、リモートデスクトップの接続設定が保存された.rdpファイルをダウンロードして実行すると、Windowsサーバーに接続します。WindowsサーバーのIDは`Administrator`であり、パスワードはNHN Cloudコンソールで確認したパスワードを使用します。

<a id="how-to-connect-serial-console"></a>
### シリアルコンソール接続方法 { #how-to-connect-serial-console }

起動の失敗、ネットワーク設定の問題など、SSHクライアントを使用できない状況では、シリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には次の制約があります。

* インスタンスごとに1つのシリアルコンソール接続のみ可能で、複数の接続を試みると正常に接続できない場合があります。
* 個人がアップロードしたイメージで作成したインスタンスとプライベートイメージで作成したインスタンスは、シリアルコンソール接続を保証しません。
* シリアルコンソールの接続は最大10分間接続できます。
* Windowsインスタンスはシリアルコンソール機能をサポートしていません。
* 2026年1月27日のリリース以前に作成したインスタンスは、**[インスタンスの停止]** 後に **[インスタンスの起動]** が必要です。**[インスタンスの再起動]** 機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスに接続して起動方法を変更した場合、起動に失敗する可能性があり、その結果に対する責任はユーザーにあります。
> 通常の状況では、SSHクライアント接続の使用をお勧めします。

<a id="how-to-connect-serial-console-change-grub-bootloader-settings"></a>
#### GRUBブートローダー設定の変更

2024年11月26日のリリース以前に作成したインスタンスでブートローダーを操作するには、GRUB設定が必要です。

GRUB設定ファイルを編集します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
```

変更した設定を適用します。OSによってGRUB設定を適用するコマンドが異なる場合があります。

```
$ sudo update-grub
```
