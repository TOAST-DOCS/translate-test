## Compute > Instance > 概要 { #compute-instance-overview }

インスタンスは仮想CPU、メモリ、ルートブロックストレージで構成された仮想サーバーです。このサーバーにお客様のサービスやアプリケーションをインストールし、NHN Cloudが提供するさまざまなサービスを組み合わせて使用します。

<a id="components"></a>

## インスタンスの構成要素 { #components }

インスタンスを構成する要素は次のとおりです。

- **イメージ**: インスタンスのオペレーションシステムを格納した仮想ディスク
- **タイプ**(flavor): インスタンスの仮想ハードウェア性能
- **アベイラビリティゾーン**(AZ, availability zone): インスタンスが作成される物理的な場所
- **キーペア**(key-pair): インスタンスへの接続に使用するキー
- **セキュリティグループ**(security groups): インスタンスのネットワークセキュリティ設定
- **ネットワーク**: インスタンスが接続される仮想ネットワーク

この情報に応じて、インスタンスの属性と使用方法が変わります。この情報のうち、イメージとアベイラビリティゾーンを除いた設定はインスタンスの作成後も変更できますが、一部のインスタンスタイプ(flavor)はインスタンスの作成後に変更することはできません。インスタンスタイプの変更については、[コンソール使用ガイドのインスタンスタイプの変更](./console-guide/#modify-flavor)を参照してください。

<a id="image"></a>
### イメージ { #image }

イメージはオペレーションシステムを格納した仮想ディスクです。NHN Cloudは現在、Debian、Ubuntu、RockyおよびWindowsをサポートしています。

すべてのイメージはインスタンスの仮想ハードウェアで最適に動作するよう設定されており、NHN Cloudのセキュリティ検証を経ているため、安全に使用できます。イメージの詳細については、[イメージの概要](/Compute/Image/ja/overview/)を参照してください。

<a id="flavor"></a>
### Instance Flavor { #flavor }

NHN Cloudはお客様の用途に合わせたさまざまなインスタンスタイプを提供します。運用するサービスまたはアプリケーションの特性に応じて、適切なタイプのインスタンスを作成できます。既存のインスタンスのタイプもWebコンソールで簡単に変更できます。

| タイプ    | 説明                                                                                                                                               |
| ------- |--------------------------------------------------------------------------------------------------------------------------------------------------|
| m2 | CPUとメモリをバランスよく設定したタイプです。サービスやアプリケーションのパフォーマンス要件が明確でない場合に使用します。                                                                               |
| c2 | CPUの性能を高く設定したインスタンスタイプです。高い演算性能が必要なWebアプリケーションサーバーや分析システムに使用します。                                                                           |
| r2 | 他のリソースに比べてメモリの使用量が多い場合に使用できます。通常、インメモリデータベースやキャッシュサーバーに使用します。                                                                               |
| t2 | 低コストのインスタンスです。作業負荷が高くないサーバーに使用します。                                                                                                          |
| u2 | 最も低コストのインスタンスです。作業負荷が高くないサーバーで使用します。<br>ローカルブロックストレージを使用するため、他のインスタンスと比較して安定性が落ちますが、低価格で利用できます。<br>このタイプのインスタンスはI/O性能を保証しません。 |
| x1 | ハイスペックのCPUとメモリをサポートするタイプです。高い性能が必要なサービスやアプリケーションに使用します。                                                                                        |

<a id="availability-zone"></a>
### Availability Zone { #availability-zone }

NHN Cloudは物理ハードウェアの問題による障害に備えるため、システム全体を複数のアベイラビリティゾーンに分割しています。各アベイラビリティゾーンには、ストレージシステム、ネットワークスイッチ、ラックスペース、電源装置がそれぞれ独立して構成されています。あるアベイラビリティゾーン内で発生した障害は他のアベイラビリティゾーンに影響を与えないため、サービス全体の可用性が向上します。インスタンスを複数のアベイラビリティゾーンに分散して構築することで、サービスの可用性をさらに高めることができます。

異なるアベイラビリティゾーン間には次のような特性があります。

- 複数のアベイラビリティゾーンに分散して作成されたインスタンス間でネットワーク通信が可能で、その際に発生するネットワーク使用料金は課金されません。
- 同じアベイラビリティゾーン内のインスタンス間ではブロックストレージを共有できますが、異なるアベイラビリティゾーン間ではブロックストレージを共有することはできません。
- 異なるアベイラビリティゾーン間でFloating IPを共有できます。あるアベイラビリティゾーンで障害が発生した場合でも、すばやく他のアベイラビリティゾーンにFloating IPを移動することで、障害時間を最小限に抑えることができます。

<a id="key-pair"></a>
### Key-pair { #key-pair }

キーペアは公開鍵基盤([PKI](https://ko.wikipedia.org/wiki/%EA%B3%B5%EA%B0%9C_%ED%82%A4_%EA%B8%B0%EB%B0%98_%EA%B5%AC%EC%A1%B0)、public key infrastructure)に基づくSSH公開鍵と秘密鍵のペアです。NHN Cloudで作成したインスタンスに接続するには、セキュリティが脆弱なキーボード入力方式のID/パスワード認証の代わりにキーペアを使用する必要があります。ユーザーはキーペアの秘密鍵を使用してログイン情報をエンコードし、インスタンスに送信して接続認証を受けた後、安全にインスタンスに接続できます。キーペアを使用したインスタンスの接続方法については、[インスタンスの接続方法](#how-to-access-instances)を参照してください。

キーペアはインスタンスの作成時にNHN Cloudコンソールで新規作成することも、お客様が作成したキーペアを登録して使用することもできます。キーペアの登録方法については、[コンソールガイドのキーペアのインポート](./console-guide/#import-key-pairs-windows)を参照してください。

> [注意]
> キーペアを新規作成すると、キーペアの秘密鍵をダウンロードします。秘密鍵は再発行できないため、ダウンロードした秘密鍵は安全なディスクやUSBドライブなどに保管してください。秘密鍵が外部に流出すると、誰でも流出した秘密鍵を使って該当インスタンスにアクセスできるため、慎重に管理する必要があります。

> [参考]
> キーペアはユーザーアカウントに割り当てられたリソースのため、プロジェクトを削除しても削除されずに維持されます。

<a id="security-groups"></a>
### Security Groups { #security-groups }

セキュリティグループはインスタンスに転送されるネットワークトラフィックを制御する仮想ファイアウォールです。セキュリティグループの詳細については、[VPCの概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

> [参考]
> デフォルトのセキュリティグループは外部からのインバウンド(in-bound)ネットワークトラフィックをすべて無視するよう設定されています。SSHでインスタンスに接続する際は、インスタンスが属するセキュリティグループでSSHポートを開放するよう設定してから接続します。

<a id="network"></a>
### ネットワーク { #network }

インスタンスが外部と通信するには、VPCで定義されたネットワークの少なくとも1つに接続されている必要があります。ネットワークに接続されていないインスタンスにはアクセスできません。ネットワークを新規作成または変更するには、[VPCの概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

<a id="pricing"></a>

## 課金 { #pricing }

インスタンスの課金方式は次のとおりです。

* インスタンスは作成した瞬間から課金されます。
* インスタンスのルートブロックストレージは、インスタンスとは別にブロックストレージの課金基準で課金されます。
* インスタンスが停止されると、90日間はWebサイト料金基準の90%割引料金が適用されます。停止状態が90日を超えると、停止状態を維持したまま通常料金に切り替わります。
* 終了したインスタンスは課金されません。

課金の詳細については、サービス別[料金ページ](https://$[ price_dom[f] ]$/kr/service/compute/instance#price)を参照してください。

## インスタンス接続方法 { #how-to-access-instances }

<a id="how-to-access-linux-instances"></a>
### Linuxインスタンス接続方法 { #how-to-access-linux-instances }

Linuxインスタンスに接続する際は、SSHクライアントを使用します。インスタンスのセキュリティグループにSSHアクセスポート(デフォルト22)が開放されていない場合、接続することはできません。SSHアクセスを許可する方法については、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。インスタンスにFloating IPが割り当てられていない場合、NHN Cloud外部から接続することはできません。Floating IPを割り当てる方法については、[VPC概要](/Network/VPC/ja/overview$[ vpc_ov ]$/)を参照してください。

<a id="how-to-access-linux-instances-from-mac-or-linux-using-an-ssh-client"></a>
#### MacまたはLinuxのSSHクライアントでLinuxインスタンスに接続する方法

MacやLinuxには通常、SSHクライアントがデフォルトでインストールされています。SSHクライアントで以下のようにキーペアの秘密鍵を使用して接続します。

Ubuntuインスタンス

	$ ssh -i my_private_key.pem ubuntu@<インスタンスのIP>

Debianインスタンス

	$ ssh -i my_private_key.pem debian@<インスタンスのIP>

Rockyインスタンス

	$ ssh -i my_private_key.pem rocky@<インスタンスのIP>

<a id="how-to-access-linux-instances-from-windows-using-putty-ssh-client"></a>
#### WindowsでPuTTY SSHクライアントを使用してLinuxインスタンスに接続する方法

PuTTY SSHクライアントは、Windowsで広く使用されているSSHクライアントプログラムです。[PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html)または韓国語パッチが適用された[iPuTTY](https://github.com/iPuTTY/iPuTTY/releases/tag/l0.70i)をインストールします。

WindowsでPuTTY SSHクライアントを使用してLinuxインスタンスに接続するには、3つの手順が必要です。

* キーペアの秘密鍵をPuTTY用秘密鍵に変換
* PuTTY用秘密鍵をPuTTYに登録
* PuTTYでインスタンスに接続

##### 1. キーペアの秘密鍵をPuTTY用秘密鍵に変換

PuTTYでは、キーペアの秘密鍵をPuTTYの秘密鍵形式に変換して使用する必要があります。鍵の変換には、PuTTYと一緒にインストールされるputtygenを使用します。

![イメージ1](http://static.toastoven.net/prod_instance/putty001.png)

**PuTTY Key生成ツール**ダイアログの最下部にある**パラメーター**で**生成するキーの種類**を**RSA**に選択し、**生成するキーのビット数**はデフォルト値の「2048」ビットを入力します。**操作**の下にある**秘密鍵ファイルの読み込み**の横の**読み込み**ボタンをクリックして、キーペアの秘密鍵ファイルを読み込みます。

![イメージ2](http://static.toastoven.net/prod_instance/putty002.png)

**操作**の下にある**生成されたキーの保存**の横の**秘密鍵の保存**ボタンをクリックして、PuTTY用に変換されたキーペアの秘密鍵を保存します。**キーのパスフレーズ**を空白のままで秘密鍵を保存すると、**パスフレーズで保護せずにこのキーを保存しますか？**というメッセージが表示されます。変換された秘密鍵をより安全に保存するには、パスフレーズを設定して保存します。

> [注意]
インスタンスに自動でログインするように設定する場合は、パスフレーズを使用しないでください。パスフレーズを使用すると、ログイン時に秘密鍵のパスワードを直接入力する必要があります。

##### 2. PuTTY用秘密鍵をPuTTYに登録

このように作成されたPuTTY用秘密鍵は、2つの方法で登録して使用できます。

* PuTTYで認証秘密鍵ファイルを登録して使用する方法
* pageant(PuTTY認証エージェント)に認証秘密鍵ファイルを登録して使用する方法

**A. PuTTYで認証秘密鍵ファイルを登録して使用する方法**


PuTTYを起動し、左側の**カテゴリ**で**接続 > SSH > Auth**を選択します。右側の**認証パラメーター**の下にある**認証秘密鍵ファイル**にPuTTY用秘密鍵を登録します。

![イメージ3](http://static.toastoven.net/prod_instance/putty005.png)

秘密鍵を登録した後、接続情報を保存しておけば、毎回秘密鍵ファイルを再登録する必要がありません。接続情報を保存する方法は、以下の接続方法を参照してください。


**B. pageant(PuTTY認証エージェント)に認証秘密鍵ファイルを登録して使用する方法**


PuTTYと一緒にインストールされるpageantを起動すると、以下の図のようにWindowsトレイにアイコンが表示されます。pageantアイコンを右クリックして**キーの追加**メニューをクリックし、PuTTY用秘密鍵を追加します。

![イメージ4](http://static.toastoven.net/prod_instance/putty006.png)

秘密鍵が追加されたことを確認するには、**キーの表示**を選択します。キーが正常に追加されると、以下の図のように追加されたキーが表示されます。

![イメージ5](http://static.toastoven.net/prod_instance/putty008.png)

pageantは一度起動すると、Windowsトレイに常駐して実行されるため、インスタンスに接続するたびに再起動する必要がありません。ただし、Windowsを再起動した場合は、再度起動する必要があります。

##### 3. PuTTYでインスタンスに接続

PuTTY用に変換された秘密鍵が正常に登録されていることを確認したら、PuTTYを起動します。

![イメージ6](http://static.toastoven.net/prod_instance/putty009.png)

基本接続情報の**ホスト名**は次のように使用します。

Ubuntu

	ubuntu@<インスタンスのIP>

Debian

	debian@<インスタンスのIP>

Rocky

	rocky@<インスタンスのIP>

**ポート**はSSHのデフォルトポートである22、**接続タイプ**は**SSH**を指定します。

すべての情報が正確であれば、セッションを保存します。**読み込み、保存、保存済みセッションの削除**で保存済みセッションの下のフィールドに保存するセッション名を入力し、**保存**ボタンをクリックしてセッションを保存します。セッションを保存しないと、2-Aで登録した秘密鍵の設定も保持されません。

**開く**をクリックすると、インスタンスに接続します。

<a id="how-to-access-windows-instances"></a>
### Windowsインスタンス接続方法 { #how-to-access-windows-instances }

Windowsサーバーに接続するには、NHN Cloudコンソールで接続するWindowsインスタンスを選択します。インスタンス詳細画面の**接続情報**タブで**パスワード確認**ボタンをクリックして、Windowsサーバーに設定されたパスワードを確認します。

**パスワード確認**で入力するキーペアの秘密鍵はサーバーに送信されず、ブラウザでパスワードを復号化する処理にのみ使用されます。

**パスワード確認**の横の**接続**ボタンをクリックして、リモートデスクトップ接続設定が保存された.rdpファイルをダウンロードして実行すると、Windowsサーバーに接続します。WindowsサーバーのIDは`Administrator`で、パスワードはNHN Cloudコンソールで確認したパスワードを使用します。

<a id="how-to-connect-serial-console"></a>
### シリアルコンソール接続方法 { #how-to-connect-serial-console }

起動の失敗、ネットワーク構成の問題など、SSHクライアントを使用できない状況でシリアルコンソールに接続してインスタンスにアクセスできます。

シリアルコンソール機能には次の制約条件があります。

* インスタンスあたり1つのシリアルコンソール接続のみ可能で、多重接続を試みた場合、正常に接続されない場合があります。
* 個人がアップロードしたイメージで作成したインスタンスとプライベートイメージで作成したインスタンスは、シリアルコンソール接続を保証しません。
* シリアルコンソール接続は最大10分間接続可能です。
* Windowsインスタンスはシリアルコンソール機能をサポートしていません。
* 2026年1月27日のリリース以前に作成したインスタンスは、**インスタンス停止**後に**インスタンス起動**が必要です。**インスタンス再起動**機能では適用されません。

> [注意]
> シリアルコンソールでインスタンスに接続して起動方法を変更した場合、起動に失敗する可能性があり、その結果に対する責任はユーザーにあります。
> 一般的な状況では、SSHクライアント接続の使用を推奨します。

<a id="how-to-connect-serial-console-change-grub-bootloader-settings"></a>
#### GRUBブートローダー設定の変更

2024年11月26日のリリース以前に作成したインスタンスでブートローダーを操作するには、GRUB設定が必要です。

GRUB設定ファイルを修正します。

```
$ sudo vi /etc/default/grub.d/50-cloudimg-settings.cfg
GRUB_TIMEOUT=3
GRUB_TERMINAL="console serial"
GRUB_SERIAL_COMMAND="serial --speed=9600 --unit=0 --word=8 --parity=no --stop=1"
```

変更した設定を適用します。OSによってGRUB設定適用コマンドが異なる場合があります。

```
$ sudo update-grub
```
