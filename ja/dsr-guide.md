## Load Balancer(DSR) 管理

<a id='create-dsr-loadbalancers'></a>
### Load Balancer(DSR) 作成
NHN Cloudコンソールでロードバランサー(DSR) の設定値を入力するだけで、簡単にDSR方式のロードバランサーを作成できます。ロードバランサー(DSR) は、DSR(direct server return) 方式で動作し、サーバーの応答トラフィックがロードバランサーを経由せずクライアントに直接送信されるため、高い処理性能を提供します。

ロードバランサー(DSR) 作成画面は、次の3つの領域で構成されます。

#### 1. Load Balancer(DSR) 基本情報設定

ロードバランサー(DSR) の基本情報を設定します。必要な項目は次のとおりです。

* 名前：ロードバランサー(DSR) の名前を入力します。
* 説明：ロードバランサー(DSR) の説明を記述します。
* VPC：ロードバランサー(DSR) が接続されるVPCを選択します。
* サブネット：ロードバランサー(DSR) が属するサブネットを選択します。ロードバランサー(DSR) とメンバーインスタンスは同一のサブネットに位置する必要があります。
* VIP(Virtual IP)：ロードバランサー(DSR) に割り当てるVIPアドレスです。割り当て方式を**自動割り当て**または**直接指定**から選択できます。
  * 自動割り当て：サブネットの利用可能IPから1つを自動的に割り当ててVIPとして使用します。
  * 直接指定：サブネットのCIDR範囲内で希望するIPを直接入力してVIPとして使用します。

!!! danger "注意"
    直接指定したVIPアドレスがサブネットのCIDR範囲に属さない場合、作成が失敗します。必ず該当サブネットのIP範囲内で指定してください。

!!! tip "参考"
    ロードバランサー(DSR) は、TCP/UDP L4レベルで動作し、サーバー応答トラフィックがロードバランサーを経由しません。したがって、一般的なロードバランサーとは異なり、L7機能(HTTPヘッダーベースのルーティング、SSL Offloading、リスナー/メンバーグループ概念など) は提供されません。

#### 2. 状態確認設定

メンバーインスタンスが正常に動作しているかを定期的に確認する状態確認を設定します。

* 状態確認プロトコル：状態確認に使用するプロトコルを選択します。**TCP / ICMP / HTTP**のいずれかを選択します。
* 遅延時間：状態確認リクエストを送信する周期(秒) です。
* 最大応答待機時間(タイムアウト) ：各状態確認リクエストのタイムアウト時間(秒) です。この時間内に応答がない場合、失敗と見なします。
* 最大リトライ回数：インスタンスを異常と判定するまでの最大リトライ回数です。(1～10回)

プロトコル別に次のような追加項目を設定します。

**TCP**

* 状態確認ポート：TCP接続を試みるポート番号を指定します。

**ICMP**

* 別途ポート設定は不要です。ICMP Echo Request/Replyで接続性を確認します。

**HTTP**

* 状態確認ポート：HTTPリクエストを送信するポート番号を指定します。
* HTTPパス(URL) ：状態確認を実行するURLパスを入力します。デフォルト値は`/`です。
* 期待HTTPレスポンスコード：正常応答と見なすHTTPレスポンスコードを入力します。デフォルト値は`200`です。

!!! danger "注意"
    遅延時間はタイムアウト以上である必要があります。タイムアウトが遅延時間より大きい場合、状態確認が正常に動作しない可能性があります。

!!! tip "参考"
    TCP/HTTP状態確認は、DSR VIPを宛先としてリクエストするため、メンバーサーバーのloインターフェイスにVIPが設定されていない場合、該当パケットが受信・処理されず状態確認が失敗し、メンバーが`INACTIVE`と判定されます。ICMP状態確認は、メンバーの実際のIPにリクエストするため、VIP設定に関係なく接続性のみを確認します。

#### 3. メンバー設定

ロードバランサー(DSR) 作成時に登録するメンバーインスタンスを指定します。メンバー登録は、ロードバランサー(DSR) 作成後にも実行できます。

* インスタンス選択：ロードバランサー(DSR) と同一のサブネットに属するインスタンス(ネットワークインターフェイス) を選択します。1つ以上のインスタンスを同時に選択してメンバーとして登録できます。

!!! tip "参考"
    ロードバランサー(DSR) は、クライアントリクエストの宛先ポート(VIPポート) をそのまま維持してメンバーインスタンスに転送します。したがって、一般的なロードバランサーとは異なり、メンバー登録時にメンバー別のサービスポートを指定せず、メンバーインスタンスのネットワークインターフェイスのみを選択します。メンバーサーバーのアプリケーションは、`0.0.0.0`またはVIPにバインドして、クライアントが送信した同一ポートを待機する必要があります。

!!! danger "注意"
    メンバーインスタンスがVIPに向かうトラフィックを正常に受信・応答するには、サーバー内部で次の設定が必要です。

    - ネットワークインターフェイスにVIPを追加許可アドレスとして追加(コンソールNetwork Interfaceメニュー)
    - カーネルパラメータ設定(`arp_ignore=1`、`arp_announce=2`)
    - loインターフェイスにVIPを`/32`サブネットとして追加
    - Security Groupsでサービスポートおよび状態確認トラフィック許可

    詳しい手順は、[ロードバランサー(DSR) 概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

!!! tip "参考"
    新規登録されたメンバーの初期状態は`INACTIVE`です。状態確認に合格すると、自動的に`ACTIVE`状態に切り替わってトラフィックを受信します。

すべての項目を入力後、**ロードバランサー作成**ボタンをクリックすると、ロードバランサー(DSR) が作成されます。

<a id='view-dsr-loadbalancers'></a>
### Load Balancer(DSR) 参照および修正

#### Load Balancer(DSR) 一覧

ロードバランサー(DSR) 作成を完了すると、一覧画面で作成されたロードバランサー(DSR) の基本情報を確認できます。一覧画面に表示される項目は次のとおりです。

* 名前：ロードバランサー(DSR) 作成時に指定した名前です。
* VIPアドレス：ロードバランサー(DSR) に割り当てられたプライベートIPです。VPC内部ではこのIPでアクセスできます。
* Floating IP：外部からアクセスするために接続されたFloating IPです。
* ネットワーク：ロードバランサー(DSR) が属するVPCの名前とサブネットCIDRです。
* メンバー数：ロードバランサー(DSR) に登録されたメンバーインスタンスの数です。
* 状態：ロードバランサー(DSR) の作成/動作状態です。

!!! tip "参考"
    ロードバランサー(DSR) の状態は、次のいずれかで決定されます。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | 正常動作中 |
    | `BUILD` | ロードバランサー(DSR) 作成中 |
    | `ERROR` | エラー発生。管理者にお問い合わせください。 |

上部の**+ DSR作成**ボタンでロードバランサー(DSR) を追加作成でき、一覧でチェックボックスでロードバランサー(DSR) を選択した後、**削除**ボタンで削除できます。

#### Load Balancer(DSR) 詳細情報

一覧でロードバランサー(DSR) を選択すると、画面下部に詳細情報が表示されます。詳細画面は、**基本情報**、**メンバー**、**状態確認**の3つのタブで区分されます。

**基本情報**タブでは、次の情報を確認できます。

* 名前、説明
* サブネットおよびVIPアドレス
* Floating IP接続情報
* 状態

#### 名前変更
ロードバランサー(DSR) の名前を変更するには、詳細情報の**名前修正**アイコンをクリックして、変更する名前を入力した後、**確認**ボタンをクリックします。

#### Floating IP変更
外部ネットワークからロードバランサー(DSR) にアクセスできるようにFloating IPを接続または分離できます。

1. ロードバランサー(DSR) 詳細情報の**Floating IP変更**ボタンをクリックします。
2. 接続するFloating IPを選択します。Floating IPを分離するには**使用しない**を選択します。
3. **確認**ボタンをクリックすると設定が適用されます。

!!! tip "参考"
    Floating IPを分離しても、VPC内部でVIPを通じたアクセスには影響ありません。

!!! tip "参考"
    ロードバランサー(DSR) が接続されたVPC、サブネット、VIPアドレスは、作成後に変更できません。変更が必要な場合は、ロードバランサー(DSR) を削除した後、再作成する必要があります。

<a id='delete-dsr-loadbalancers'></a>
### Load Balancer(DSR) 削除
ロードバランサー(DSR) 一覧画面で削除するロードバランサー(DSR) を選択した後、**削除**ボタンをクリックし、確認ウィンドウで**確認**ボタンをクリックすると、該当ロードバランサー(DSR) が削除されます。

!!! danger "注意"
    ロードバランサー(DSR) を削除すると、該当DSRに登録されたすべてのメンバーが一緒に削除されます。Floating IPが接続されている場合は自動的に解除されます。

## メンバー管理

ロードバランサー(DSR) 一覧で希望するロードバランサー(DSR) を選択した後、**メンバー**タブをクリックすると、メンバーインスタンス管理画面が表示されます。

### メンバー一覧

**メンバー**タブでは、ロードバランサー(DSR) に登録されたメンバーインスタンスの一覧と状態を確認できます。一覧に表示される項目は次のとおりです。

* IPアドレス：メンバーインスタンスのIPアドレスです。
* デバイスモデル：メンバーとして登録されたネットワークポートの所有リソースタイプです。
* デバイス情報：メンバーとして登録されたネットワークポートの識別情報(インスタンス名、ポートIDなど) が統合されて表示されます。
* 状態：メンバーの現在状態です。

!!! tip "参考"
    ロードバランサー(DSR) は、クライアントリクエストの宛先ポートをそのまま維持してメンバーに転送するため、メンバー項目にはL4サービスポートが別途表示されません。実際のサービスポートは、クライアントがVIPにリクエストしたポートであり、メンバーサーバーのアプリケーションが該当ポートを待機(Listen) する必要があります。

!!! tip "参考"
    メンバーの状態は、次のいずれかで決定されます。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | 状態確認成功、トラフィック分散対象 |
    | `INACTIVE` | 状態確認失敗または新規登録直後、トラフィック分散対象から除外 |
    | `ONLINE` | メンバーが手動で非活性化された状態 |

<a id='add-dsr-members'></a>
### メンバー追加
**メンバー**タブで**+ メンバー追加**ボタンをクリックすると、メンバー追加モーダルが表示されます。

1. 一覧でメンバーとして登録する**インスタンス**を選択します。1つ以上のインスタンスを同時に選択できます。
2. **確認**ボタンをクリックすると、選択したインスタンスがメンバーとして登録されます。

!!! tip "参考"
    一般的なロードバランサーとは異なり、ロードバランサー(DSR) はメンバー追加段階でL4サービスポートを入力しません。ロードバランサー(DSR) がクライアントリクエストの宛先ポートを変換せずそのままメンバーに転送するため、メンバー別のポートマッピングが不要です。

!!! danger "注意"
    メンバー登録時は次の制約事項にご注意ください。

    * メンバーインスタンスは、ロードバランサー(DSR) と同一のサブネットに属する必要があります。
    * コンピューターインスタンスのみメンバーとして登録できます。
    * 同一のインスタンスポートを同じロードバランサー(DSR) に重複して登録することはできません。
    * 1つのロードバランサー(DSR) には、基本的に最大30個のメンバーを登録できます。

!!! tip "参考"
    メンバー登録後、トラフィックを正常に受信するには、ネットワークインターフェイスにVIPを追加許可アドレスとして追加し、メンバーサーバー内部でARPカーネルパラメータ設定、loインターフェイスにVIP追加、Security Groups規則設定が必要です。詳しい手順は、[ロードバランサー(DSR) 概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

<a id='delete-dsr-members'></a>
### メンバー削除
メンバータブの一覧で削除するメンバーを選択した後、**削除**ボタンをクリックします。確認ウィンドウが表示されたら、**確認**ボタンをクリックすると、該当メンバーがロードバランサー(DSR) から除去されます。

!!! tip "参考"
    ロードバランサー(DSR) からメンバーを削除しても、該当インスタンス自体は削除されません。反対に、メンバーとして登録されたインスタンスを削除すると、該当メンバーは自動的にロードバランサー(DSR) から除去されます。

## 状態確認管理

ロードバランサー(DSR) 詳細画面の**状態確認**タブで、現在設定された状態確認情報を確認して変更できます。

<a id='view-dsr-health-monitor'></a>
### 状態確認照会
**状態確認**タブでは、現在設定された状態確認の次の情報を確認できます。

* 状態確認プロトコル：TCP / ICMP / HTTP
* 状態確認ポート：TCPまたはHTTPプロトコル使用時の状態確認対象ポート
* 遅延時間：状態確認リクエスト周期(秒)
* 最大応答待機時間：状態確認タイムアウト(秒)
* 最大リトライ回数：異常判定までのリトライ回数
* HTTPパス(URL) / 期待HTTPレスポンスコード：HTTPプロトコル使用時のみ表示

<a id='change-dsr-health-monitor'></a>
### 状態確認設定変更
**状態確認**タブで**設定変更**ボタンをクリックすると、状態確認設定を変更できます。

* 状態確認プロトコル：TCP / ICMP / HTTPから選択
* プロトコル別必須項目を入力します。
  * TCP：状態確認ポート
  * ICMP：追加項目なし
  * HTTP：状態確認ポート、HTTPパス、期待HTTPレスポンスコード
* 遅延時間、最大応答待機時間、最大リトライ回数を設定します。

設定完了後、**確認**ボタンをクリックすると変更事項が適用されます。

!!! danger "注意"
    遅延時間はタイムアウト以上である必要があります。タイムアウトが遅延時間より大きい場合、状態確認が正常に動作しない可能性があります。

!!! tip "参考"
    状態確認リクエストは、ロードバランサー(DSR) と同一のサブネットに自動割り当てされた状態確認専用IPから送信されます。メンバーインスタンスのSecurity Groupで該当トラフィックを許可する必要があり、状態確認が正常動作します。詳しい内容は、[ロードバランサー(DSR) 概要](/Network/Load%20Balancer(DSR)/ja/overview/)のSecurity Groups設定セクションを参照してください。

<a id='dsr-quota'></a>
## クォータおよび制限事項

ロードバランサー(DSR) 使用時は次のようなクォータおよび制限が適用されます。

| 項目 | デフォルト制限 | 説明 |
|--|--|--|
| プロジェクトあたりのロードバランサー(DSR) 数 | 10個 | プロジェクトあたりで作成可能なロードバランサー(DSR) 数 |
| ロードバランサー(DSR) あたりのメンバー数 | 30個 | 1つのロードバランサー(DSR) に登録可能なメンバー数 |

!!! tip "参考"
    デフォルトクォータを超えて使用する場合は、カスタマーサポートにお問い合わせください。
