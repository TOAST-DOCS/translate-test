## ロードバランサー(DSR)管理

<a id='create-dsr-loadbalancers'></a>
### ロードバランサー(DSR)作成
NHN Cloudコンソールでロードバランサー(DSR)設定値を入力するだけで、簡単にDSR方式のロードバランサーを作成できます。ロードバランサー(DSR)はDSR(direct server return)方式で動作し、サーバーの応答トラフィックがロードバランサーを経由せずにクライアントに直接送信されるため、高い処理性能を提供します。

ロードバランサー(DSR)作成画面は、次の3つの領域で構成されます。

#### 1. ロードバランサー(DSR)基本情報設定

ロードバランサー(DSR)の基本情報を設定します。必要な項目は次のとおりです。

* 名前：ロードバランサー(DSR)の名前を入力します。
* 説明：ロードバランサー(DSR)の説明を記述します。
* VPC：ロードバランサー(DSR)が接続されるVPCを選択します。
* サブネット：ロードバランサー(DSR)が属するサブネットを選択します。ロードバランサー(DSR)とメンバーインスタンスは同じサブネットに位置する必要があります。
* VIP(Virtual IP)：ロードバランサー(DSR)に割り当てるVIPアドレスです。割り当て方式を**自動割り当て**または**直接指定**から選択できます。
  * 自動割り当て：サブネットの使用可能なIPの中から1つを自動で割り当ててVIPとして使用します。
  * 直接指定：サブネットのCIDR範囲内で希望するIPを直接入力してVIPとして使用します。

!!! danger "注意"
    直接指定したVIPアドレスがサブネットのCIDR範囲に属さない場合、作成に失敗します。必ず該当サブネットのIP範囲内で指定してください。

!!! tip "参考"
    ロードバランサー(DSR)はTCP/UDP L4レベルで動作し、サーバー応答トラフィックがロードバランサーを経由しません。したがって、一般的なロードバランサーとは異なり、L7機能(HTTPヘッダベースルーティング、SSL Offloading、リスナー/メンバーグループ概念など)は提供されません。

#### 2. ヘルスチェック設定

メンバーインスタンスが正常に動作しているかを定期的に確認するヘルスチェックを設定します。

* ヘルスチェックプロトコル：ヘルスチェックで使用するプロトコルを選択します。**TCP / ICMP / HTTP**の中から1つを選択します。
* 遅延時間：ヘルスチェックリクエストを送信する周期(秒)です。
* 最大応答待機時間(タイムアウト)：各ヘルスチェックリクエストのタイムアウト時間(秒)です。この時間内に応答がない場合、失敗とみなします。
* 最大再試行回数：インスタンスを異常と判定するまでの再試行最大回数です。(1～10回)

プロトコル別に次のように追加項目を設定します。

**TCP**

* ヘルスチェックポート：TCP接続を試行するポート番号を指定します。

**ICMP**

* 別途ポート設定は不要です。ICMP Echo Request/Replyで接続性を確認します。

**HTTP**

* ヘルスチェックポート：HTTPリクエストを送信するポート番号を指定します。
* HTTPパス(URL)：ヘルスチェックを実行するURLパスを入力します。デフォルト値は`/`です。
* 期待HTTP応答コード：正常応答とみなすHTTP応答コードを入力します。デフォルト値は`200`です。

!!! danger "注意"
    遅延時間はタイムアウトより大きいか等しい必要があります。タイムアウトが遅延時間より大きいと、ヘルスチェックが正常に動作しない場合があります。

!!! tip "参考"
    TCP/HTTPヘルスチェックはDSR VIPを宛先にリクエストするため、メンバーサーバーのloインターフェースにVIPが設定されていない場合、該当パケットが受信・処理されずにヘルスチェックが失敗し、メンバーが`INACTIVE`と判定されます。ICMPヘルスチェックはメンバーの実際のIPにリクエストするため、VIP設定とは関係なく接続性のみ確認します。

#### 3. メンバー設定

ロードバランサー(DSR)作成時に登録するメンバーインスタンスを指定します。メンバー登録はロードバランサー(DSR)作成後にも可能です。

* インスタンス選択：ロードバランサー(DSR)と同じサブネットに属するインスタンス(ネットワークインターフェース)を選択します。1つ以上のインスタンスを同時に選択してメンバーとして登録できます。

!!! tip "参考"
    ロードバランサー(DSR)は、クライアントリクエストの宛先ポート(VIPポート)をそのまま維持してメンバーインスタンスに転送します。したがって、一般的なロードバランサーとは異なり、メンバー登録時にメンバー別サービスポートを指定せず、メンバーインスタンスのネットワークインターフェースのみ選択します。メンバーサーバーのアプリケーションは`0.0.0.0`またはVIPにバインドされ、クライアントが送信した同じポートを受信待機する必要があります。

!!! danger "注意"
    メンバーインスタンスがVIPからのトラフィックを正常に受信・応答するには、サーバー内部で次の設定が必要です。

    - ネットワークインターフェースにVIPを追加許可アドレスとして追加(コンソールNetwork Interfaceメニュー)
    - カーネルパラメータ設定(`arp_ignore=1`、`arp_announce=2`)
    - loインターフェースにVIPを`/32`サブネットとして追加
    - Security Groupsでサービスポートおよびヘルスチェックトラフィック許可

    詳細な手順は[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参考してください。

!!! tip "参考"
    新しく登録されたメンバーの初期状態は`INACTIVE`です。ヘルスチェックを通過すると自動で`ACTIVE`状態に転換されてトラフィックを受信します。

すべての項目入力後、**ロードバランサー作成**ボタンをクリックするとロードバランサー(DSR)が作成されます。

<a id='view-dsr-loadbalancers'></a>
### ロードバランサー(DSR)確認および修正

#### ロードバランサー(DSR)リスト

ロードバランサー(DSR)作成を完了すると、リスト画面で作成されたロードバランサー(DSR)の基本情報を確認できます。リスト画面で表示される項目は次のとおりです。

* 名前：ロードバランサー(DSR)作成時に指定した名前です。
* VIPアドレス：ロードバランサー(DSR)に割り当てられたプライベートIPです。VPC内部ではこのIPでアクセスできます。
* Floating IP：外部からアクセスするために接続されたFloating IPです。
* ネットワーク：ロードバランサー(DSR)が属するVPCの名前とサブネットCIDRです。
* メンバー数：ロードバランサー(DSR)に登録されたメンバーインスタンスの個数です。
* 状態：ロードバランサー(DSR)の作成/動作状態です。

!!! tip "参考"
    ロードバランサー(DSR)の状態は次のいずれかで決まります。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | 正常動作中 |
    | `BUILD` | ロードバランサー(DSR)作成中 |
    | `ERROR` | エラー発生。管理者にお問い合わせください。 |

上部の**+ DSR作成**ボタンでロードバランサー(DSR)を追加作成でき、リストでチェックボックスでロードバランサー(DSR)を選択後、**削除**ボタンで削除できます。

#### ロードバランサー(DSR)詳細情報

リストでロードバランサー(DSR)を選択すると画面下部に詳細情報が表示されます。詳細画面は**基本情報**、**メンバー**、**ヘルスチェック**の3つのタブに分かれています。

**基本情報**タブでは次の情報を確認できます。

* 名前、説明
* サブネットおよびVIPアドレス
* Floating IP接続情報
* 状態

#### 名前変更
ロードバランサー(DSR)の名前を変更するには、詳細情報の**名前修正**アイコンをクリックして変更する名前を入力後、**確認**ボタンをクリックします。

#### Floating IP変更
外部ネットワークからロードバランサー(DSR)にアクセスできるようにFloating IPを接続または分離できます。

1. ロードバランサー(DSR)詳細情報の**Floating IP変更**ボタンをクリックします。
2. 接続するFloating IPを選択します。Floating IPを分離するには**使用しない**を選択します。
3. **確認**ボタンをクリックすると設定が適用されます。

!!! tip "参考"
    Floating IPを分離してもVPC内部でのVIPを通じたアクセスには影響しません。

!!! tip "参考"
    ロードバランサー(DSR)が接続されたVPC、サブネット、VIPアドレスは作成後変更できません。変更が必要な場合はロードバランサー(DSR)を削除してから再作成する必要があります。

<a id='delete-dsr-loadbalancers'></a>
### ロードバランサー(DSR)削除
ロードバランサー(DSR)リスト画面で削除するロードバランサー(DSR)を選択後、**削除**ボタンをクリックして確認ウィンドウで**確認**ボタンをクリックすると、該当ロードバランサー(DSR)が削除されます。

!!! danger "注意"
    ロードバランサー(DSR)を削除すると、該当DSRに登録されたすべてのメンバーが一緒に削除されます。Floating IPが接続されている場合、自動で解除されます。

## メンバー管理

ロードバランサー(DSR)リストで希望するロードバランサー(DSR)を選択後、**メンバー**タブをクリックするとメンバーインスタンス管理画面が表示されます。

### メンバーリスト

**メンバー**タブでは、ロードバランサー(DSR)に登録されたメンバーインスタンスのリストと状態を確認できます。リストに表示される項目は次のとおりです。

* IPアドレス：メンバーインスタンスのIPアドレスです。
* デバイスモデル：メンバーとして登録されたネットワークポートの所有リソースタイプです。
* デバイス情報：メンバーとして登録されたネットワークポートの識別情報(インスタンス名、ポートIDなど)が統合されて表示されます。
* 状態：メンバーの現在の状態です。

!!! tip "参考"
    ロードバランサー(DSR)はクライアントリクエストの宛先ポートをそのまま維持してメンバーに転送するため、メンバー項目にはL4サービスポートが別途表示されません。実際のサービスポートはクライアントがVIPにリクエストしたポートであり、メンバーサーバーのアプリケーションが該当ポートを受信待機(Listen)する必要があります。

!!! tip "参考"
    メンバーの状態は次のいずれかで決まります。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | ヘルスチェック成功、トラフィック分散対象 |
    | `INACTIVE` | ヘルスチェック失敗または新規登録直後、トラフィック分散対象から除外 |
    | `ONLINE` | メンバーが手動で非活性化された状態 |

<a id='add-dsr-members'></a>
### メンバー追加
**メンバー**タブで**+ メンバー追加**ボタンをクリックするとメンバー追加モーダルが表示されます。

1. リストでメンバーとして登録する**インスタンス**を選択します。1つ以上のインスタンスを同時に選択できます。
2. **確認**ボタンをクリックすると選択したインスタンスがメンバーとして登録されます。

!!! tip "参考"
    一般的なロードバランサーとは異なり、ロードバランサー(DSR)はメンバー追加段階でL4サービスポートを入力しません。ロードバランサー(DSR)がクライアントリクエストの宛先ポートを変換せずにそのままメンバーに転送するため、メンバー別ポートマッピングが不要です。

!!! danger "注意"
    メンバー登録時、次の制約事項にご注意ください。

    * メンバーインスタンスはロードバランサー(DSR)と同じサブネットに属する必要があります。
    * Computeインスタンスのみメンバーとして登録できます。
    * 同じインスタンスポートを同じロードバランサー(DSR)に重複登録できません。
    * 1つのロードバランサー(DSR)には基本的に最大30個のメンバーを登録できます。

!!! tip "参考"
    メンバー登録後、トラフィックを正常に受信するには、ネットワークインターフェースにVIPを追加許可アドレスとして追加し、メンバーサーバー内部でARPカーネルパラメータ設定、loインターフェースにVIP追加、Security Groups規則設定が必要です。詳細な手順は[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参考してください。

<a id='delete-dsr-members'></a>
### メンバー削除
メンバータブのリストで削除するメンバーを選択後、**削除**ボタンをクリックします。確認ウィンドウが表示されたら**確認**ボタンをクリックすると、該当メンバーがロードバランサー(DSR)から除去されます。

!!! tip "参考"
    ロードバランサー(DSR)からメンバーを削除しても該当インスタンス自体は削除されません。逆に、メンバーとして登録されたインスタンスを削除すると、該当メンバーは自動でロードバランサー(DSR)から除去されます。

## ヘルスチェック管理

ロードバランサー(DSR)詳細画面の**ヘルスチェック**タブで現在設定されたヘルスチェック情報を確認し、変更できます。

<a id='view-dsr-health-monitor'></a>
### ヘルスチェック照会
**ヘルスチェック**タブでは、現在設定されたヘルスチェックの次の情報を確認できます。

* ヘルスチェックプロトコル：TCP / ICMP / HTTP
* ヘルスチェックポート：TCPまたはHTTPプロトコル使用時のヘルスチェック対象ポート
* 遅延時間：ヘルスチェックリクエスト周期(秒)
* 最大応答待機時間：ヘルスチェックタイムアウト(秒)
* 最大再試行回数：異常判定までの再試行回数
* HTTPパス(URL) / 期待HTTP応答コード：HTTPプロトコル使用時にのみ表示

<a id='change-dsr-health-monitor'></a>
### ヘルスチェック設定変更
**ヘルスチェック**タブで**設定変更**ボタンをクリックするとヘルスチェック設定を変更できます。

* ヘルスチェックプロトコル：TCP / ICMP / HTTPから選択
* プロトコル別必須項目を入力します。
  * TCP：ヘルスチェックポート
  * ICMP：追加項目なし
  * HTTP：ヘルスチェックポート、HTTPパス、期待HTTP応答コード
* 遅延時間、最大応答待機時間、最大再試行回数を設定します。

設定完了後、**確認**ボタンをクリックすると変更事項が適用されます。

!!! danger "注意"
    遅延時間はタイムアウトより大きいか等しい必要があります。タイムアウトが遅延時間より大きいと、ヘルスチェックが正常に動作しない場合があります。

!!! tip "参考"
    ヘルスチェックリクエストは、ロードバランサー(DSR)と同じサブネットに自動割り当てされたヘルスチェック専用IPから送信されます。メンバーインスタンスのSecurity Groupで該当トラフィックを許可する必要があり、ヘルスチェックが正常動作します。詳細は[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のSecurity Groups設定セクションを参考してください。

<a id='dsr-quota'></a>
## クォータおよび制限事項

ロードバランサー(DSR)使用時、次のようなクォータおよび制限が適用されます。

| 項目 | 基本制限 | 説明 |
|--|--|--|
| プロジェクト当たりロードバランサー(DSR)数 | 10個 | プロジェクト当たり作成可能なロードバランサー(DSR)個数 |
| ロードバランサー(DSR)当たりメンバー数 | 30個 | 1つのロードバランサー(DSR)に登録可能なメンバー個数 |

!!! tip "参考"
    基本クォータを超過して使用する必要がある場合は、カスタマーサポートにお問い合わせください。
