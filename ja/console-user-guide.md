## Machine Learning > NHN Cloud Foundry > コンソール使用ガイド { #foundry.console.guide }

このドキュメントでは、NHN Cloud Foundry コンソールでデータソース、パイプライン、分析（クエリ・チャート・ダッシュボード）、アプリを管理する方法を説明します。

設定項目の表の必須列は次を意味します。

- `O`: 必ず入力が必要な項目
- `X`: 任意の項目
- `O*`: 他の設定値によって必須かどうかが変わる項目

<a id="status"></a>

## 現況 { #status }

コンソールパス: **Machine Learning > NHN Cloud Foundry > 現況** タブ

現況タブでサービスの有効化状態とテナント設定を確認します。サービスを使用するには、まずこのタブで有効化状態を確認し、有効化されていない場合は有効化を申請する必要があります。

<a id="status.activate"></a>

### サービス有効化の申請 { #status.activate }

サービスの有効化はコンソールから直接実行できません。[1:1お問い合わせ](https://www.nhncloud.com/kr/support/inquiry)で希望するリソースサイズを含めてお問い合わせください。申請したクラスターが作成されると、データソースの作成から順番に使用できます。

リソースサイズ別に使用できる機能は次のとおりです。

| 値 | 説明 |
| --- | --- |
| SMALL | 基本リソース: データソース、共通機能、チャートクエリが使用可能 |
| MEDIUM | 基本 + データパイプラインが追加で使用可能 |
| LARGE | 基本 + AI アプリが使用可能 |
| XLARGE | すべての機能が使用可能（データパイプライン + AI アプリ） |

<a id="status.info"></a>

### サービス状態の確認 { #status.info }

有効化後は、現況タブで次の情報を確認できます。

| 項目 | 説明 |
| --- | --- |
| サービス状態 | 現在のサービスの有効化状態 |
| テナントドメイン | サービスにアクセスする際に使用するドメイン |

- 有効化後にリソースの変更が必要な場合も、1:1お問い合わせで申請します。
- サービス環境を構成または整理中の場合は、進捗率が一緒に表示されます。
- **[無効化]** ボタンをクリックすると、サービスを無効化できます。

!!! danger "注意"
    サービスを無効化すると、作成されたすべてのリソースが削除され、この操作は元に戻すことはできません。

<a id="datasource"></a>

## データソース { #datasource }

コンソールパス: **Machine Learning > NHN Cloud Foundry > データソース** タブ

データソースは、NHN Cloud Foundry で分析するデータを保存する単位です。データソースの作成、照会、削除はコンソールで実行します。

<a id="datasource.list"></a>

### データソース一覧 { #datasource.list }

データソース一覧画面で次の情報を確認できます。

| カラム | 説明 |
| --- | --- |
| タイプ | データソースの種類 |
| データソース名 | データソースを識別する名前 |
| テーブル名 | データが保存されるテーブル名 |
| 状態 | データソースの現在の状態 |
| 作成日 | データソースが作成された日時 |
| 詳細 | 虫眼鏡アイコンをクリックすると詳細情報を照会 |

タイプ:

| 値 | 説明 |
| --- | --- |
| ファイル | アップロードした CSV ファイルで作成したデータソース |
| 推薦 | 推薦結果が保存されるデータソース |
| データセット | パイプラインが作成したデータソース |

状態:

| 値 | 説明 |
| --- | --- |
| INITIALIZING | データソースを初期化しています。 |
| PROCESSING | データを処理しています。 |
| INGESTING | データを積載しています。 |
| COMPLETED | データソースの処理が完了しました。 |
| FAILED | データソースの処理に失敗しました。 |
| DELETING | データソースを削除しています。 |

タイプがファイルのデータソースは、最新のファイルアップロード結果が状態の横にアイコンで一緒に表示されます。

| 値 | 説明 |
| --- | --- |
| 反映中 | 最新のアップロードファイルを反映しています。 |
| 確認推奨 | 最新のアップロードファイルは反映されましたが、確認が必要な事項があります。データソースの詳細で内容を確認してください。 |
| 確認必要 | データソースは使用可能ですが、最新のアップロードファイルは反映されていません。ファイルを確認してから再アップロードしてください。 |

- 状態バッジ横の疑問符アイコンにマウスを合わせると、状態の説明が表示されます。
- 上部の検索機能でデータソース名または ID を基準にフィルタリングできます。
- タイプ・データソース名・テーブル名・状態カラムはカラムヘッダーのフィルターでも絞り込めます。
- ページあたりの表示件数を調整できます（10件、20件、50件 / デフォルト 10件）。

!!! tip "注意"
    タイプが推薦、データセットの項目はユーザーが直接作成できません。推薦は推薦システムアプリを作成するとき、データセットはパイプラインを実行するときに自動的に作成されます。

<a id="datasource.create"></a>

### データソースの作成 { #datasource.create }

**[データソース作成]** ボタンをクリックすると、作成モーダルが開きます。

<a id="datasource.create.basic"></a>

#### 基本設定 { #datasource.create.basic }

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| データソース名 | O | 英字、数字、-、_ を使用（1〜255文字） |
| テーブル名 | O | 英小文字、数字、_ を使用（1〜255文字） |
| 説明 | X | データソースの説明 |

<a id="datasource.create.detail"></a>

#### 詳細設定 { #datasource.create.detail }

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| CSV ファイル | X | **[ファイル選択]** ボタンでアップロードする CSV ファイルを選択（最大 100MB） |
| ヘッダー設定 | X | 「最初の行がヘッダーです」をチェックすると、CSV の先頭行をカラム名として使用 |
| 基本キーフィールド | X | カンマ区切りで入力（例: user_id,item_id） |
| スキーマ | O | データのフィールド名とタイプの定義 |

スキーマは次の方法で入力します。

- タイプ推論: CSV ファイルを選択してから **[タイプ推論]** ボタンをクリックすると、CSV 先頭のサンプル（最大 1,000行）からカラムタイプを推論してスキーマ入力欄を補完します。誤って推論されたタイプは直接修正します。
- 表編集: **[フィールド追加]** ボタンで行を追加し、各行にフィールド名とタイプを指定します。備考列にはタイプ推論結果のうち確認が必要な項目が表示されます。
- JSON 編集: **[JSON で直接編集]** ボタンをクリックし、次の形式の JSON 配列を直接入力します。

スキーマ JSON 形式の例:

```json
[
  { "fieldName": "hostname", "fieldType": "string" },
  { "fieldName": "portName", "fieldType": "string" },
  { "fieldName": "trafficIn", "fieldType": "double" },
  { "fieldName": "eventTimestamp", "fieldType": "timestamp" }
]
```

サポートするフィールドタイプ:

| 値 | 説明 |
| --- | --- |
| boolean | ブール値 |
| int | 整数（32bit） |
| long | 整数（64bit） |
| float | 実数（32bit） |
| double | 実数（64bit） |
| string | 文字列 |
| timestamp | タイムスタンプ |
| datetime | 日時（YYYY-MM-DD HH:MM:SS） |
| date | 日付 |
| array | 配列（基本） |
| array&lt;double&gt; | double 配列 |
| array&lt;int&gt; | int 配列 |
| array&lt;string&gt; | string 配列（推薦モデル用） |
| array&lt;float&gt; | float 配列（推薦モデル用） |

!!! danger "注意"
    予約フィールド名 `system_eventTimestamp` は使用できません。

設定完了後、**[追加]** ボタンをクリックするとデータソースが作成されます。

<a id="datasource.delete"></a>

### データソースの削除 { #datasource.delete }

一覧で削除するデータソースをチェックボックスで選択してから **[削除]** ボタンをクリックします。

- 削除時にテーブルと積載されたデータも一緒に削除されます。
- 収集作業が進行中の場合は削除できません。

<a id="datasource.detail"></a>

### 詳細表示 / プレビュー { #datasource.detail }

- **[詳細]**（虫眼鏡アイコン）: データソースの情報を確認します。
- **[プレビュー]**（⌄ アイコン）: 積載されたデータをテーブル形式でプレビューします。

詳細表示は次のタブで構成されます。

| タブ | 説明 |
| --- | --- |
| 接続情報 | データソース ID、データソース名、テーブル名、タイプ、説明、状態 |
| カタログ | フィールド名とデータ型の一覧照会、**[フィールド追加]** |

<a id="datasource.edit"></a>

### データの更新 { #datasource.edit }

データソース名とテーブル名は作成後に変更できません。積載されたデータは新しい CSV ファイルで更新し、フィールドは追加できます。

<a id="datasource.edit.csv"></a>

#### CSV でデータを修正 { #datasource.edit.csv }

一覧でタイプがファイルのデータソース行のその他（⋯）メニューから **[CSV で修正する]** をクリックします。

1. 既存のカラム一覧を確認します。
2. **[ファイル選択]** ボタンで新しい CSV ファイルを選択します（最大 100MB）。
3. 選択したファイルのプレビューと確認事項を確認します。
4. **[上書き]** ボタンをクリックするとアップロードが開始され、進捗は一覧画面で確認します。

アップロードが制限される場合は次のとおりです。

| 状況 | 案内 |
| --- | --- |
| ファイルのカラム数が既存のカラム数より多い | カタログにフィールドを先に追加してから再アップロードします。 |
| カタログにないカラムが含まれている | カタログにフィールドを先に追加してから再アップロードします。 |
| ヘッダー設定とファイルの先頭行が一致しない | カラム名行があるファイルでアップロードするか、データソースのヘッダー設定を変更します。 |

<a id="datasource.edit.field"></a>

#### フィールドの追加 { #datasource.edit.field }

詳細表示の **[カタログ]** タブで **[フィールド追加]** ボタンをクリックします。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| フィールド名 | O | 英字または _ で始まり、英字、数字、_ のみ使用 |
| タイプ | O | スキーマでサポートするフィールドタイプから選択 |
| 説明 | X | フィールドの説明 |

- **[行追加]** ボタンで一度に最大 20件まで追加できます。
- システム予約フィールド名および既存のフィールド名は使用できません。

!!! tip "注意"
    コンソールだけでなく API でもデータを更新できます。使用方法は [API ガイド](./api-guide/#ingest.api) の「Ingest API」を参照してください。

<a id="pipeline"></a>

## パイプライン { #pipeline }

コンソールパス: **Machine Learning > NHN Cloud Foundry > パイプライン** タブ

パイプラインは、データソースのデータをノードを接続したワークフローで処理し、分析可能なデータセットに変換する機能です。

<a id="pipeline.list"></a>

### パイプライン一覧 { #pipeline.list }

パイプラインメニューに移動すると、作成されたパイプラインの一覧がテーブル形式で表示されます。

| カラム | 説明 |
| --- | --- |
| チェックボックス | パイプラインの選択 |
| 有効化 | 有効化状態のアイコン |
| パイプライン名 | パイプラインを識別する名前 |
| バッチスケジュール | 設定されたスケジュール。未設定の場合はハイフンで表示 |
| 開始日時 | スケジュールの開始日時 |
| 終了日時 | スケジュールの終了日時 |
| 最終実行日時 | 最新の実行日時 |
| パイプライン状態 | パイプラインの現在の状態 |
| 手動実行 | 実行ボタン |

- 行をクリックすると編集画面に移動します。
- 実行中のパイプラインは手動実行の位置に進捗表示が現れ、実行できない状態ではボタンが無効化されます。

ツールバーでパイプラインの作成、修正、削除、有効化、無効化を実行できます。有効化と無効化はその他（⋯）メニューにあります。

<a id="pipeline.create"></a>

### パイプラインの作成 { #pipeline.create }

1. 一覧画面で **[パイプライン作成]** ボタンをクリックします。
2. 右側の **[設定パネル]** で基本情報を入力します。

    | 項目 | 必須 | 説明 |
    | --- | --- | --- |
    | パイプライン名 | O | パイプラインを識別する名前（最大 255文字） |
    | パイプライン説明 | X | パイプラインの補足説明（最大 255文字） |
    | タグ | X | 分類のためのタグ（最大 10個、各 50文字） |

3. **[作成]** ボタンをクリックすると、パイプラインが下書き状態で作成されます。

!!! danger "注意"
    有効化されたパイプラインの設定を保存すると、パイプラインが無効化されます。実行ボタンを押してビルドすると自動的に有効化されます。

<a id="pipeline.editor"></a>

### パイプラインエディター { #pipeline.editor }

パイプラインの作成・編集時に表示されるメイン編集画面です。

- **ヘッダー**: パイプライン名、説明、戻るボタン
- **タブバー（左側）**: 実行/停止、実行履歴、ソースノード追加ボタン
- **タブバー（右側）**: 最終実行日時、状態/ビルド/有効化バッジ、保存ボタン
- **エディター領域**: ノード・エッジ編集（ドラッグ＆ドロップ、自動整列をサポート）
- **サイドパネル**: 設定、スケジュール、コンピューティングリソースパネル

<a id="pipeline.status"></a>

#### パイプラインの状態 { #pipeline.status }

状態バッジにマウスを合わせると、ツールチップで詳細説明を確認できます。

| 値 | 説明 |
| --- | --- |
| 下書き | パイプラインが作成され、ノードが存在しない状態です。 |
| 修正済み | パイプラインの設定が変更され、再ビルド（実行）が必要な状態です。 |
| ビルド中 | パイプラインをビルドしています。しばらくお待ちください。 |
| 待機 | パイプラインのビルドが完了し、実行準備ができた状態です。 |
| 実行中 | パイプラインが現在実行中です。 |
| 完了 | パイプラインの実行が正常に完了しました。 |
| 失敗 | パイプラインの実行が停止またはエラーが発生しました。 |
| 終了 | ユーザーがパイプラインの実行を停止しました。 |
| 削除中 | パイプラインを削除しています。 |

<a id="pipeline.node"></a>

### ノード構成 { #pipeline.node }

パイプラインは、以下の5種類のノードを組み合わせて構成します。

| ノードタイプ | 役割 | 入力 | 出力 | 説明 |
| --- | --- | --- | --- | --- |
| Source（ソースノード） | データ原本 | なし | データ | 外部データソースを接続 |
| Transform（変換ノード） | データ加工 | データ | 変換されたデータ | フィルタ、派生カラム、集計、ラベルエンコーディングなど |
| Join（ジョインノード） | テーブル結合 | 2つのデータ | 結合されたデータ | Inner/Left/Right/Full Outer/Semi/Anti ジョイン |
| Union（ユニオンノード） | テーブル統合 | 2つのデータ | 統合されたデータ | Full Merge/Intersect Merge/Left-First Merge |
| Dataset（出力ノード） | 出力テーブル | データ | なし | テーブルとして結果を保存（最終ノード） |

接続の制約事項：

- SOURCE ノードには入力を接続できません（ルートノード）。
- DATASET ノードには出力を接続できません（最終ノード）。
- 循環参照（ループ）や自分自身との接続はできません。

!!! danger "注意"
    パイプラインを実行するには、必ず1つ以上の DATASET ノードが存在する必要があります。

<a id="pipeline.node.source"></a>

#### ソースノードの追加 { #pipeline.node.source }

1. タブバーで **[ソースノード追加]** ボタンをクリックします。
2. 使用可能なデータソースの一覧がモーダルで表示されます。
3. 目的のソースを選択して追加します。

| 値 | 説明 |
| --- | --- |
| FILE | CSV ファイルデータソース |
| 추천 | 推薦結果リポジトリ |
| データセット | パイプラインの Dataset ノードが生成したデータ。別のパイプラインの入力として再利用できます |

<a id="pipeline.node.transform"></a>

#### 変換ノード（TRANSFORM） { #pipeline.node.transform }

変換作業ごとにノード名（最大30文字、英字・数字・`-`・`_`・韓国語）を指定します。1つのノードに複数の変換作業を追加すると、順序に従って接続されたノードが生成されます。

サポートする変換メソッドは次のとおりです。

| 分類 | メソッド | 説明 |
| --- | --- | --- |
| Row（行単位演算） | Filter | 条件に合う行のみ抽出 |
| Row（行単位演算） | Explode | デリミタ文字列を行に分解 |
| Row（行単位演算） | Derive | ホワイトリスト関数で派生カラムを生成 |
| Aggregation（集計演算） | Aggregate | グループ化および集計 |
| Window（ウィンドウ演算） | Rank Top N | グローバル並べ替え＋上位 N 件 |
| Column（カラム演算） | Label Encode FIT | カテゴリ → 整数マッピングテーブルを生成 |
| Column（カラム演算） | Label Encode Apply | マッピングテーブルでエンコーディングを適用 |
| LLM（LLM ベース演算） | Classify | LLM でテキストをカテゴリに分類 |

<a id="pipeline.node.transform.filter"></a>

##### フィルタ（Filter） { #pipeline.node.transform.filter }

| 値 | 説明 | 例 |
| --- | --- | --- |
| = | 等しい | field = 'value' |
| ≠ | 等しくない | field ≠ 'value' |
| > | 超過 | field > 100 |
| ≥ | 以上 | field ≥ 100 |
| &lt; | 未満 | field < 100 |
| ≤ | 以下 | field ≤ 100 |
| LIKE | パターンマッチング | field LIKE '%keyword%' |
| IN | リスト含有 | field IN ('a', 'b', 'c') |
| IS NULL | NULL かどうか | field IS NULL |
| IS NOT NULL | NOT NULL かどうか | field IS NOT NULL |

選択したカラムのタイプに応じて、使用可能な演算子のみ表示されます。

| カラムタイプ | 使用可能な演算子 |
| --- | --- |
| 文字列 | =、≠、LIKE、IN、IS NULL、IS NOT NULL |
| 数値 | =、≠、>、≥、&lt;、≤、IN、IS NULL、IS NOT NULL |
| 日付/時刻 | =、≠、>、≥、&lt;、≤、IS NULL、IS NOT NULL |
| 真偽値 | =、≠、IS NULL、IS NOT NULL |

比較する値は **[直接入力]**、**[時間（現在基準）]**、**[別のカラム]** の中から選択します。

論理演算子は `AND`、`OR` をサポートしており、**[グループ追加]** ボタンで条件を最大3段階まで묶ことができます。

<a id="pipeline.node.transform.explode"></a>

##### 分解（Explode） { #pipeline.node.transform.explode }

デリミタでつながれた文字列カラムを、トークンごとに別々の行に分解します。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 分解するカラム | O | デリミタでつながれた文字列が格納されたカラム |
| 出力カラム名 | O | 分解された各トークンを格納するカラム名 |
| デリミタ | O | デフォルトはカンマ（,） |
| 空白除去 | X | ON の場合、各トークンの前後の空白を除去 |
| 空トークン除去 | X | ON の場合、分解後の空文字列トークンを行から除外 |
| 出力タイプ | X | STRING、BIGINT、INT、DOUBLE。未指定時は STRING |
| 保持する元のカラム | X | 結果に含める元のカラム。選択しない場合はすべての元のカラムが保持される |

- デリミタは正規表現として解釈されるため、特殊文字はエスケープが必要です（例：`\.`、`\|`）。
- 出力タイプを指定すると、分解された値が指定したタイプに変換されます。たとえば、数値 ID がカンマ区切りの場合に BIGINT を指定すると、ジョインキーのタイプを合わせることができます。

<a id="pipeline.node.transform.derive"></a>

##### 派生カラム（Derive） { #pipeline.node.transform.derive }

提供される関数を使用して、既存のカラムから新しいカラムを作成します。**[派生カラム追加]** ボタンで定義を複数追加でき、各定義ごとに関数と派生カラム名を指定します。

| 値 | 説明 | 追加設定 |
| --- | --- | --- |
| DATE_BUCKET | 日付バケット（epoch ms → 指定タイムゾーンの日付） | ソースカラム、タイムゾーン（例：Asia/Seoul） |
| JSON_ARRAY_LENGTH | JSON 配列の要素数 | ソースカラム、要素スキーマ |
| CONCAT | 複数のカラムをデリミタで結合 | ソースカラム2つ以上、デリミタ、デフォルト値（任意） |
| RATIO | 分子/分母の比率計算 | 分子、分母、倍数（任意、デフォルト1）、丸め桁数（任意） |
| COALESCE | 複数のカラムのうち最初の非 null 値 | ソースカラム2つ以上 |

- 定義は上から下の順に適用され、前に作成した派生カラムを後の定義のソースカラムとして参照できます。
- 派生カラム名には英字、数字、アンダースコア、韓国語を使用できます。

<a id="pipeline.node.transform.aggregate"></a>

##### 集計（Aggregate） { #pipeline.node.transform.aggregate }

1. **[グループ化基準の選択]**（任意）：同じ値を持つ行をグループとしてまとめます。選択しない場合は全データを1つのグループとして集計します。
2. **[集計関数の定義]**（必須）：集計するカラム、集計関数、結果カラム名を指定します。複数追加できます。

| 値 | 説明 |
| --- | --- |
| COUNT | 件数 |
| COUNT_DISTINCT | 一意の値の件数 |
| SUM | 合計 |
| AVG | 平均 |
| MIN | 最小値 |
| MAX | 最大値 |
| FIRST | 最初の値 |
| LAST | 最後の値 |
| STDDEV | 標準偏差 |
| VARIANCE | 分散 |
| ARRAY_AGG | グループの値を配列として収集 |

- COUNT は集計するカラムとして `*（全体）` を選択できます。
- FIRST と LAST は並べ替え基準カラムと方向（昇順/降順）を指定し、並べ替え後の最初または最後の値を取得します。

ARRAY_AGG を選択すると、次の設定が追加されます。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 配列要素の種類 | O | 単一カラムまたは JSON オブジェクト |
| 収集するカラム | O* | 配列要素の種類が単一カラムの場合は必須。配列に格納するカラム |
| JSON オブジェクトフィールド定義 | O* | 配列要素の種類が JSON オブジェクトの場合は必須。キー名とカラムの組み合わせ |
| 配列要素の並べ替え | X | 並べ替え基準カラムと方向。未指定時は並べ替えなし |
| 出力形式 | O | STRUCT_ARRAY、JSON_STRING_ARRAY、JSON_STRING |
| 重複除去（DISTINCT） | X | 並べ替えを設定すると無視される |

<a id="pipeline.node.transform.rank"></a>

##### ランキング（Rank Top N） { #pipeline.node.transform.rank }

全データを指定した基準で並べ替え、上位 N 件の行のみを残します。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 並べ替え基準 | O | 並べ替えるカラムと方向（DESC / ASC） |
| 上位 N 件 | O | 並べ替え後に結果に含める行数 |
| 結果順位カラム名 | O | 結果に追加される 1〜N の順位カラムの名前 |

- **[並べ替え基準追加]** ボタンで基準を複数指定すると、第1ソート、第2ソートの順に適用され、ドラッグして順序を変更できます。
- 照会時に順位カラムで並べ替えると、元の順序を維持できます。

<a id="pipeline.node.transform.label.encode"></a>

##### ラベルエンコーディング（Label Encode FIT / Label Encode Apply） { #pipeline.node.transform.label.encode }

カテゴリ型データを数値（整数）に変換する機能です。**FIT（学習）** と **APPLY（適用）** の2段階で構成されており、必ず FIT ノードを先に作成してから APPLY ノードで参照する必要があります。

FIT ノードの設定：

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| エンコードするカラムの選択 | O | ラベルエンコーディングを適用するカラム（1つ以上） |
| 開始インデックス | X | エンコーディングの開始値（デフォルト：0） |

APPLY ノードの設定：

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| マッピングテーブルノードの選択 | O | FIT ノードを選択 |
| 元のカラムを上書き | X | チェック時、元のカラムをエンコード済みの値で置き換え（デフォルト：無効） |
| 結果カラムの接尾辞 | X | 元のカラムを保持する場合に新しいカラム名に付く接尾辞（デフォルト：_encoded） |

!!! tip "注記"
    マッピングテーブルに存在しない値（OOV、Out-of-Vocabulary）は `-1` としてエンコードされます。

!!! danger "注意"
    FIT を再実行すると、データの変更に伴いエンコーディング番号が変わる場合があります。既存モデルとの互換性にご注意ください。

<a id="pipeline.node.transform.classify"></a>

##### 分類（Classify） { #pipeline.node.transform.classify }

LLM を使用して、テキストカラムの値をカテゴリに分類します。分類基準となるカテゴリ一覧は、別のデータソースノードとして準備する必要があります。

パイプラインが実行されると、入力データの行をバッチサイズ分まとめてバッチあたり1回 LLM を呼び出します。各呼び出しのプロンプトにはカテゴリ一覧とそのバッチの行が含まれ、LLM が行ごとに適切なカテゴリ ID を返すと、その結果が分類結果カラムとして保存されます。

**LLM 設定**

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| LLM プロバイダー | O | Claude |
| モデル名 | O | claude-haiku-4-5、claude-sonnet-4-6 |
| API キー | O | 使用する LLM の API キー。このパイプラインにのみ保存され、保存後は再表示されません |
| バッチサイズ | X | 1回の LLM 呼び出しに含める行数（1〜30） |
| 最大リトライ数 | X | 呼び出し失敗時のリトライ回数（0〜10） |
| タイムアウト（秒） | X | 呼び出し待機時間（1〜600） |
| 増分分類 | X | 変更された行のみ LLM で分類し、変更のない行は前回の実行結果を再利用 |

**入力カラム**

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 入力カラム | O | LLM に渡すカラム。複数選択可能 |
| カラム結合デリミタ | X | 複数の入力カラムの値を連結する際に使用するデリミタ |
| ユーザープロンプトテンプレート | X | 行ごとの入力値構成テンプレート。{{ カラム名 }} パターンが該当カラムの値に置換されます。設定すると結合デリミタより優先適用されます。入力カラムで選択したカラムのみ参照できます |

**軸（カテゴリテーブル）**

分類基準となるカテゴリ一覧を軸として登録します。軸は最大5つまで追加できます。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| カテゴリノード | O | カテゴリ一覧が格納されたデータソースノード |
| カテゴリ ID カラム | O | カテゴリを識別するカラム |
| カテゴリ名カラム | O | カテゴリ名のカラム |
| カテゴリメタデータカラム | X | カテゴリの説明、判定基準などの追加カラム。プロンプトとともに渡され、分類精度を高めます |
| 分類結果カラム（配列） | O | 分類結果を格納する配列カラム名 |
| 代表カラム | X | 最も代表的な分類 ID を保存するカラム名。空欄の場合は生成しません |

**出力**

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 出力タイプ | O | SINGLE_LABEL、MULTI_LABEL |
| 分類根拠カラム | X | LLM が提供した分類根拠を保存するカラム名。空欄の場合は根拠を要求しないため、トークンコストが削減されます |
| コンテンツ根拠カラム | X | 入力コンテンツから生成した短い説明を保存するカラム名 |
| コンテンツ根拠最大長 | X | コンテンツ根拠カラムの最大文字数（1〜200） |

**システムプロンプト**（任意）：LLM に役割と分類基準を指示します。設定しない場合はデフォルトのプロンプトが使用されます。

!!! danger "注意"
    処理する行数が多いほど、LLM の呼び出し回数とトークン使用量が比例して増加し、コストが上がります。大規模なデータは、まず小規模で検証してコストと品質を確認してから適用することをお勧めします。

## 分析 - クエリ { #query }

コンソールパス: **Machine Learning > NHN Cloud Foundry > 分析** タブ > **クエリ** タブ

SQL を使用してデータソースのデータを照会・分析します。

<a id="query.run"></a>

### クエリの実行 { #query.run }

1. **[データソース]** を選択します。
2. **[クエリ選択]** で保存されたクエリを読み込みます。選択したデータソースで保存したクエリがある場合はリストに表示されます。読み込まずに直接作成することもできます。
3. クエリ入力欄に SQL を記述します。
4. **[行制限]** を選択します（10、100、1,000、10,000、100,000 / デフォルト: 1,000）。
5. **[クエリ実行]** ボタンを押します。

- 実行結果はデータグリッド形式で表示されます。カラム構造はクエリ結果に応じて動的に生成され、ページネーションをサポートします。
- **[初期化]** ボタンを押すと、作成したクエリが消去されます。
- **[クエリ結果のダウンロード]** ボタンを押すと、結果が CSV ファイルとして保存されます（ファイル名: `クエリ名_日付_時刻.csv`）。
- FROM 句には、データソースリストに表示されているテーブル名をそのまま使用します（`SELECT * FROM {テーブル名}`）。
- 単一の SELECT 文のみ実行できます。それ以外の構文は拒否されます。

<a id="query.save"></a>

### 保存されたクエリの変更 { #query.save }

**[クエリ選択]** で読み込んだクエリの内容を修正した後、**[クエリ保存]** ボタンを押すと変更内容が保存されます。クエリを読み込んでいない場合や内容を変更していない場合は、ボタンが無効化されます。

| カラム | 説明 |
| --- | --- |
| クエリ名 | 保存時に指定した名前 |
| クエリ構文 | 保存された SQL |
| 詳細 | クエリ全体の内容を照会 |

- クエリ名で検索できます。
- **[追加]** ボタンで新しいクエリを登録し、クエリを選択した後 **[修正]** または **[削除]** ボタンで編集または削除します。削除したクエリは復元できません。

追加・修正時に入力する項目は次のとおりです。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| クエリ名 | O | クエリを識別するための名前 |

| 構文 | O | 実行する SQL |

| カラム | 説明 |
| --- | --- |

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| X 軸 | O* | 横軸に使用するフィールド。Pie チャートでは表示されません |
| 集計間隔 | O* | 5 分、15 分、30 分、45 分、1 時間、2 時間、6 時間、12 時間、1 日、3 日、7 日。Line・Bar チャートでのみ表示されます |
| 基準時間 | O | データの時間範囲の指定 |
| カラム | O | 集計対象のカラムと集計関数の選択。1 つ以上必要 |

| フィルタ | X | データフィルタリング条件の設定 |
| 並べ替え | X | 並べ替えカラムと方向。Pie・Bar チャートでのみ表示されます |

チャート可視化タイプ別に必要な設定は次のとおりです。

| チャート可視化タイプ | 必須設定 |

| Scatter | カラム 1 つ以上 |

Bar チャートに並べ替えを指定すると、時間軸の代わりに Top-N カテゴリとして表示されます。

#### 詳細設定 { #app.create.detail }

**[モデル追加]** ボタンでモデルカードを追加します。1つのアプリに複数のモデルをまとめて構成でき、モデルカードごとに以下のセクションを設定します。

<a id="app.create.detail.model"></a>

##### 基本モデル設定 { #app.create.detail.model }

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| モデル名 | O | 使用する推薦モデルを選択します |
| Longtailモード | X | 有効にすると、人気度が低いアイテムも推薦に含まれます |

選択できるモデルは次のとおりです。

| 名前 | 説明 |
| --- | --- |
| Cold User | 新規ユーザーなど、まだ活動履歴が少ないユーザーに対して、アイテム自体の属性を基に推薦します。 |
| Warm User (Transformer) | ユーザーが最近インタラクションしたアイテムの順序を基に、次のアイテムを推薦します。 |
| Warm User (Graph) | ユーザーがインタラクションしたアイテムと類似するアイテムを、グラフ関係を基に推薦します。 |

同じモデルであっても、Longtailモードが異なる場合は別のモデルとして追加できます。

<a id="app.create.detail.resources"></a>

##### サービングリソース設定 { #app.create.detail.resources }

モデルごとのサービングコンテナに割り当てるリソースを指定します。入力しない場合はデフォルト値が適用されます。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| CPU request / CPU limit | X | Core単位。デフォルト値 2 / 4 |
| メモリ request / メモリ limit | X | Gi単位。デフォルト値 4 / 4 |

requestはlimitを超えることはできません。

<a id="app.create.detail.schedule"></a>

##### バッチスケジュール設定 { #app.create.detail.schedule }

| 周期 | 設定項目 |
| --- | --- |
| 毎日 | 時、分 |
| 毎週 | 曜日、時、分 |
| 毎時 | 時間間隔、分 |

設定した時刻は、接続しているブラウザのタイムゾーンを基準に適用されます。

##### 追加設定 (Skills) { #app.create.detail.extra }

<a id="app.detail.recommend"></a>

#### 推薦API呼び出し { #app.detail.recommend }

推薦リクエストのパラメータを入力して推薦APIを直接呼び出し、結果を確認できます。画面は入力フォーム、リクエストプレビュー、推薦結果の3つの領域で構成されます。

入力フォーム:

| 項目 | 説明 |
| --- | --- |
| 推薦アプリID | 呼び出し対象のアプリID。現在のアプリが自動入力されます |
| ユーザーID | 推薦対象ユーザーを選択します |
| 推薦モード | Normal Flow（履歴ベース）、Cold Start（属性ベース）から選択します |
| 最大推薦数 | レスポンスに含める最大アイテム数 |
| Longtailモード | 人気のないアイテムも含めて推薦の多様性を高めます。Cold Startモードでは使用できません |
| context | 推薦リクエストのコンテキスト情報（現在・最近閲覧したアイテムなど）をフィールド単位で追加します |
| userAttributes | ユーザー属性情報（グループ、年齢、関心事など）をフィールド単位で追加します |
| options | 推薦リクエストのオプションをフィールド単位で追加します |

- **[リクエストプレビュー]**: 入力値で構成された実際のAPIリクエストJSONを表示します。**[コピー]** ボタンでコピーしてAPI連携開発に活用できます。
- **[推薦結果]**: **[推薦リクエスト]** ボタンをクリックすると、ランキング、アイテムキー、スコアおよび推薦理由が表示され、総結果数とレスポンス時間も合わせて確認できます。

!!! tip "ヒント"
    推薦APIの呼び出しは、アプリがアクティブ状態のときのみ可能です。

#### アプリ情報 { #app.detail.info }
