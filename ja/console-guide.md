## メンバー管理

ロードバランサー(DSR)リストから目的のロードバランサー(DSR)を選択した後、**メンバー**タブをクリックするとメンバーインスタンス管理画面が表示されます。

### メンバーリスト

**メンバー**タブでは、ロードバランサー(DSR)に登録されたメンバーインスタンスのリストと状態を確認できます。リストに表示される項目は以下の通りです。

* IPアドレス：メンバーインスタンスのIPアドレスです。
* デバイスモデル：メンバーとして登録されたネットワークポートの所有リソースタイプです。
* デバイス情報：メンバーとして登録されたネットワークポートの識別情報（インスタンス名、ポートIDなど）が統合されて表示されます。
* 状態：メンバーの現在の状態です。

!!! tip "知っておく"
    ロードバランサー(DSR)はクライアントリクエストの宛先ポートをそのまま維持してメンバーに転送するため、メンバー項目にはL4サービスポートが別途表示されません。実際のサービスポートはクライアントがVIPにリクエストしたポートであり、メンバーサーバーのアプリケーションが該当ポートを待機(Listen)する必要があります。

!!! tip "知っておく"
    メンバーの状態は以下のいずれかで決定されます。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | ヘルスチェック成功、トラフィック分散対象 |
    | `INACTIVE` | ヘルスチェック失敗または新規登録直後、トラフィック分散対象から除外 |
    | `ONLINE` | メンバーが手動で無効化された状態 |

<a id='add-dsr-members'></a>
### メンバー追加
**メンバー**タブで**+ メンバー追加**ボタンをクリックすると、メンバー追加モーダルが表示されます。

1. リストからメンバーとして登録する**インスタンス**を選択します。1つ以上のインスタンスを同時に選択できます。
2. **確認**ボタンをクリックすると、選択したインスタンスがメンバーとして登録されます。

!!! tip "知っておく"
    一般的なロードバランサーとは異なり、ロードバランサー(DSR)はメンバー追加段階でL4サービスポートを入力しません。ロードバランサー(DSR)がクライアントリクエストの宛先ポートを変換せずにそのままメンバーに転送するため、メンバー別ポートマッピングが不要です。

!!! danger "注意"
    メンバー登録時は以下の制約事項にご注意ください。

    * メンバーインスタンスは、ロードバランサー(DSR)と同一のサブネットに属する必要があります。
    * コンピュートインスタンスのみメンバーとして登録できます。
    * 同一のインスタンスポートを同じロードバランサー(DSR)に重複して登録することはできません。
    * 1つのロードバランサー(DSR)には基本的に最大30個のメンバーを登録できます。

!!! tip "知っておく"
    メンバー登録後にトラフィックを正常に受信するには、ネットワークインターフェースにVIPを追加許可アドレスとして追加し、メンバーサーバー内部でARPカーネルパラメータ設定、loインターフェースにVIP追加、Security Groups規則設定が必要です。詳細な手順は[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

<a id='delete-dsr-members'></a>
### メンバー削除
メンバータブのリストから削除するメンバーを選択した後、**削除**ボタンをクリックします。確認ウィンドウが表示されたら**確認**ボタンをクリックすると、該当メンバーがロードバランサー(DSR)から削除されます。

!!! tip "知っておく"
    ロードバランサー(DSR)からメンバーを削除しても、該当インスタンス自体は削除されません。逆に、メンバーとして登録されたインスタンスを削除すると、該当メンバーは自動的にロードバランサー(DSR)から削除されます。

## ヘルスチェック管理

Load Balancer (DSR) 詳細画面の**ヘルスチェック**タブで、現在設定されているヘルスチェック情報を確認し、変更できます。

<a id='view-dsr-health-monitor'></a>
### ヘルスチェック照会
**ヘルスチェック**タブでは、現在設定されているヘルスチェックの以下の情報を確認できます。

* ヘルスチェックプロトコル: TCP / ICMP / HTTP
* ヘルスチェックポート: TCPまたはHTTPプロトコル使用時のヘルスチェック対象ポート
* 遅延時間: ヘルスチェック要求周期（秒）
* 最大応答待機時間: ヘルスチェックタイムアウト（秒）
* 最大再試行回数: 異常判定までの再試行回数
* HTTP経路（URL）/ 期待HTTP応答コード: HTTPプロトコル使用時のみ表示

<a id='change-dsr-health-monitor'></a>
### ヘルスチェック設定変更
**ヘルスチェック**タブで**設定変更**ボタンをクリックすると、ヘルスチェック設定を変更できます。

* ヘルスチェックプロトコル: TCP / ICMP / HTTPから選択
* プロトコル別必須項目を入力します。
  * TCP: ヘルスチェックポート
  * ICMP: 追加項目なし
  * HTTP: ヘルスチェックポート、HTTP経路、期待HTTP応答コード
* 遅延時間、最大応答待機時間、最大再試行回数を設定します。

設定完了後、**確認**ボタンをクリックすると変更事項が適用されます。

!!! danger "注意"
    遅延時間はタイムアウトより大きいか等しくなければなりません。タイムアウトが遅延時間より大きいと、ヘルスチェックが正常に動作しない場合があります。

!!! tip "参考"
    ヘルスチェック要求は、Load Balancer (DSR) と同じサブネットに自動割り当てされたヘルスチェック専用IPから送信されます。メンバーインスタンスのSecurity Groupで該当トラフィックを許可する必要があります。詳細は[Load Balancer (DSR) 概要](/Network/Load%20Balancer(DSR)/ja/overview/)のSecurity Groups設定セクションを参照してください。

## クォータと制限事項

ロードバランサー(DSR)使用時、以下のクォータと制限が適用されます。

| 項目 | デフォルト制限 | 説明 |
|--|--|--|
| プロジェクト当たりのロードバランサー(DSR)数 | 10個 | プロジェクト当たりで作成可能なロードバランサー(DSR)の個数 |
| ロードバランサー(DSR)当たりのメンバー数 | 30個 | 一つのロードバランサー(DSR)に登録可能なメンバーの個数 |

!!! tip "注意"
    デフォルトクォータを超えて使用する必要がある場合は、カスタマーサポートにお問い合わせください。
