## Network > Peering Gateway > コンソール使用ガイド { #network-peering-gateway-console-user-guide }

コンソールでPeering Gatewayサービスを使用する方法を説明します。

<a id="peering"></a>

## ピアリング { #peering }

**ピアリング**は、異なる2つの**VPC**を接続する機能です。通常、VPCはネットワーク領域が異なるため、互いに通信できません。**フローティングIP**を使用して接続することはできますが、ネットワーク使用量に応じて追加費用を支払う必要があります。ただし、ピアリング機能を使用すると、追加費用を支払わずに2つの**VPC**を接続できます。

* ピアリングは異なる2つのVPCを接続します。VPCを越えて別のVPCへの接続はサポートしていません。`A <-> B <-> C`の接続では、`A`と`C`は接続されません。
* ピアVPCを経由して別のVPCへの接続を希望する場合は、ピアリングが提供する**ルート**設定を使用して、VMインスタンスを経由してパケットが転送されるように設定する必要があります。

    !!! tip "ポイント"
        ルートの使用方法については、下記「共通機能 > ルート」を参照してください。

* 2つのVPCのIPアドレス領域が重なる場合は使用できません。<br>
  IPアドレス領域の一方が他方に包含される関係になってはならず、この場合はピアリング作成に失敗します。
* 韓国リージョンを除くその他のリージョンでは、**基本ルーティングテーブル**に接続されたサブネットでのみ通信できます。

    !!! tip "ポイント"
        ピアリングを作成すると、基本ルーティングテーブルにピアリング通信をルーティングするために、相手VPCのIPアドレス範囲へのパケットをピアリングゲートウェイに転送するルーティングルールが暗黙的に追加されます。そのため、基本ルーティングテーブルに相手VPCのIPアドレス範囲をCIDRとする別のルートを設定することはできません。また、相手VPCのIPアドレス範囲の一部をCIDRとして指定するルートを追加した場合、ピアリング通信用のルートより優先度が高くなるため、ピアリング通信ができなくなる可能性がありますので注意が必要です。

* 韓国リージョンでは、ピアリングを作成した後、ピアリングした両方のVPCのルーティングテーブルに別途ルートを設定する必要があります。
    * ルートの**[対象CIDR]**に相手VPCのIPアドレス領域を入力し、ゲートウェイ一覧でピアリングの名前を持つ**[PEERING]**項目を選択してルートを追加します。
    * ルートを追加したルーティングテーブルに接続されたサブネットでのみ通信できます。
    * 基本ルーティングテーブル以外のルーティングテーブルにもルートを追加すると、ルーティングテーブルに接続されたサブネットでピア通信が可能です。
    * ピアリング作成時にサブネットがないVPCを指定した場合、ピアリングは作成に失敗します。

<a id="create-a-peering"></a>
### ピアリング作成 { #create-a-peering }

1. **Network > Peering Gateway > ピアリング**に移動します。
2. **[ピアリング作成]**ボタンをクリックします。
3. **[名前]**、**[説明]**を入力し、**[ローカルVPC]**、**[ピアVPC]**を選択後、**[確認]**ボタンをクリックします。

<a id="change-a-peering"></a>
### ピアリング変更 { #change-a-peering }

1. **Network > Peering Gateway > ピアリング**に移動します。
2. ピアリング一覧から変更するピアリングを選択します。
3. **[ピアリング変更]**ボタンをクリックします。
4. ピアリングの**[名前]**または**[説明]**を変更し、**[確認]**ボタンをクリックします。

<a id="delete-a-peering"></a>
### ピアリング削除 { #delete-a-peering }

1. **Network > Peering Gateway > ピアリング**に移動します。
2. ピアリング一覧から削除するピアリングを選択します。
3. **[ピアリング削除]**ボタンをクリックします。

<a id="other-important-notes-on-retrieving-peering-ports-using-the-api"></a>
### (その他) APIを使用したピアリングポート照会時の注意事項 { #other-important-notes-on-retrieving-peering-ports-using-the-api }

APIを使用してピアリングに関連するポートを照会する場合、ピアリングリソースに**ピアID**が存在するかどうかによって照会方法が異なります。

!!! tip "ポイント"
    ピアIDの確認方法については、下記「参考資料 > ピアIDの確認方法」を参照してください。

* **ピアID**がない場合: 従来と同様にピアリングIDのみで照会します。
    * GET /v2.0/ports?device_id={ピアリングID}
* **ピアID**がある場合: ピアリングIDとピアIDを両方渡すことで、両方のVPCのポートをすべて照会できます。
    * GET /v2.0/ports?device_id={ピアリングID}&device_id={ピアID}

<a id="region-peering"></a>

## リージョンピアリング { #region-peering }

**リージョンピアリング**は、異なるリージョンに作成された2つの**VPC**を接続する機能です。同じリージョンのVPCはピアリングを使用して接続できますが、リージョンが異なるVPCを接続することはできません。しかし、リージョンピアリングを使用すると、リージョンが異なる2つのVPCを接続できます。

* リージョンピアリングは、異なるリージョンの2つのVPCを接続します。別のVPCを経由してさらに別のVPCへ接続することはサポートしていません。たとえば、`A <-> B <-> C`の接続では、`A`と`C`は接続されません。
* ピアVPCを経由して別のVPCへ接続したい場合は、ピアリングで提供される**ルート**設定を使用して、VMインスタンスを経由してパケットが転送されるよう設定する必要があります。

    !!! tip "ポイント"
        ルートの使用方法については、下記「共通機能 > ルート」を参照してください。

* 同一プロジェクト、別プロジェクトのどちらにも接続できます。
* リージョンピアリングを作成すると、接続された別のリージョンで自動的に作成されます。
* リージョンピアリングを削除すると、接続された別のリージョンで自動的に削除されます。
* 2つのVPCのIPアドレス領域が重複している場合は使用できません。
* 重複したVPC接続は作成できません。
* ピアリングされた両方のVPCの**ルーティングテーブル**に別途**ルート**を設定することで、通信が可能になります。
    * ルートの**対象CIDR**に相手VPCのIPアドレス領域を入力し、ゲートウェイリストからリージョンピアリングの名前を持つ**INTER_REGION_PEERING**項目を選択してルートを追加します。
    * ルートを追加したルーティングテーブルに接続されたサブネットのみ通信できます。
    * 基本ルーティングテーブル以外のルーティングテーブルにルートを追加すると、そのルーティングテーブルに接続されたサブネットからピアリング通信が可能になります。
    * リージョンピアリング作成時にサブネットのないVPCを指定すると、リージョンピアリングの作成に失敗します。

<a id="create-a-region-peering"></a>
### リージョンピアリング作成 { #create-a-region-peering }

!!! tip "ポイント"
    異なるプロジェクト間でリージョンピアリングを作成するには、ピアプロジェクトのピアリング許可対象管理に自プロジェクトのテナントIDとVPC IDが許可されている必要があります。同一プロジェクト内でリージョンピアリングを作成する場合は必要ありません。
    異なるプロジェクト間でリージョンピアリングを作成する前に、ピアプロジェクトの管理者にテナントIDとVPC IDを伝え、ピアリング許可対象管理への情報登録を依頼する必要があります。
    ピアプロジェクトで情報登録が完了したら、次の手順に従ってプロジェクトピアリングを作成できます。
    ピアリング許可対象管理の使用方法については、下記「共通機能 > ピアリング許可対象管理」を参照してください。

1. **Network > Peering Gateway > リージョンピアリング**に移動します。
2. **[リージョンピアリング作成]**ボタンをクリックします。
3. **[名前]**、**[ローカルVPC]**、**[ピアリージョン]**を選択します。
4. **[ピアテナント]**を選択します。
    * **[同一テナント]**を選択した場合、追加で入力する項目はありません。
    * **[別テナント]**を選択した場合、**[ピアテナントID]**を入力する必要があります。

    !!! tip "ポイント"
        ピアテナントIDについては、下記「参考資料」を参照してください。

5. **[ピアVPC ID]**を入力します。

    !!! tip "ポイント"
        ピアVPC IDについては、下記「参考資料」を参照してください。

<a id="delete-a-region-peering"></a>
### リージョンピアリング削除 { #delete-a-region-peering }

1. **Network > Peering Gateway > リージョンピアリング**に移動します。
2. ピアリングリストから削除するリージョンピアリングを選択します。
3. **[リージョンピアリング削除]**ボタンをクリックします。

<a id="common-feature"></a>

## 共通機能 { #common-feature }

ピアリング（ピアリング、リージョンピアリング、プロジェクトピアリング）で提供する共通機能について説明します。

<a id="manage-peering-allowed-targets"></a>
### ピアリング許可対象管理 { #manage-peering-allowed-targets }

リージョンピアリング、プロジェクトピアリングページのサブメニューで、他のプロジェクト間のピアリング接続要求を受け取る側が設定できます。要求を送信するVPCのピアテナントIDとピアVPC IDを入力してピアリング許可VPCに追加した後、ピアが送信する要求を承認できるようにします。

<a id="manage-peering-allowed-targets-add-an-peering-allowed-target"></a>
#### ピアリング許可対象追加

1. **Network > Peering Gateway > リージョンピアリング**または**Network > Peering Gateway > プロジェクトピアリング**に移動します。
2. **[ピアリング許可対象管理]**ボタンをクリックします。
3. **[ピアリング許可VPC追加]**ボタンをクリックします。
4. **[名前]**、**[ピアテナントID]**、**[ピアVPC ID]**を入力し、**[確認]**ボタンをクリックします。

    !!! tip "ポイント"
        ピアテナントIDとピアVPC IDの確認方法については、下記の「参考資料」を参照してください。

<a id="manage-peering-allowed-targets-delete-a-peering-allowed-target"></a>
#### ピアリング許可対象削除

1. **Network > Peering Gateway > リージョンピアリング**または**Network > Peering Gateway > プロジェクトピアリング**に移動します。
2. **[ピアリング許可対象管理]**ボタンをクリックします。
3. ピアリング許可VPCの一覧で、削除する対象の削除ボタンをクリックします。

<a id="route"></a>
### ルート { #route }

ピアリングで提供する**ルート**設定を使用すると、ピアVPCのVMインスタンスを経由して他のVPCにトラフィックを転送する構成を作成できます。ピアリングのルートは、ピアリングから流入するすべてのトラフィックを処理するVMインスタンスのポートおよび仮想IPポートを指定して設定できます。ルートのゲートウェイとなるVMインスタンスにはNetwork Virtual Appliance VMを配置し、VMインスタンス内部でトラフィックを制御して他のピアリングにトラフィックを転送できます。
* ピアリングでHub & Spoke形態のVPC接続を構成し、ハブVPCに位置するNetwork Virtual Applianceですべてのトラフィックを制御する構成は、ピアリングのルーティング機能を活用して構成できます。

<a id="route-create-route"></a>
#### ルート作成

1. ルートを設定するピアリングを選択します。
2. 下部タブでルートを選択します。
3. **[ルート変更]**ボタンをクリックします。

    !!! tip "ポイント"
        ピアリングの場合、2種類のボタンがあります。ピアルート変更はピアリング作成時に選択したピアVPCにルートを追加するものであり、ローカルルート変更はローカルVPCの位置を意味します。

4. **+**ボタンをクリックします。
5. 対象CIDRを入力します。
6. ゲートウェイを選択します。

    !!! tip "ポイント"
        ゲートウェイはインスタンスと仮想IPのみ選択できます。

7. **[確認]**ボタンをクリックします。

<a id="route-delete-route"></a>
#### ルート削除

1. ルート設定を削除するピアリングを選択します。
2. 下部タブでルートを選択します。
3. **[ルート変更]**ボタンをクリックします。

    !!! tip "ポイント"
        ピアリングの場合、2種類のボタンがあります。ピアルート変更はピアリング作成時に選択したピアVPCにルートを追加するものであり、ローカルルート変更はローカルVPCの位置を意味します。

4. 削除対象の**-**ボタンをクリックします。
5. **[確認]**ボタンをクリックします。

## 参考資料 { #other-considerations }

<a id="how-to-check-peer-vpc-id"></a>
### ピアVPC IDの確認方法 { #how-to-check-peer-vpc-id }

次の手順で、ピアの**VPC ID**を確認できます。

!!! tip "ポイント"
    ピアVPCが属するプロジェクトにアクセス権限がない場合は、ピアプロジェクトの管理者からVPC IDを入手してください。

1. ピアプロジェクトのコンソール画面にアクセスします。
2. **Network > VPC > 管理**に移動します。
3. ピアリング対象のVPCを選択します。
4. **[基本情報] > VPC名**に表記されたUUID値をコピーします。

<a id="how-to-check-the-peer-tenant-id"></a>
### ピアテナントIDの確認方法 { #how-to-check-the-peer-tenant-id }

次の手順で、ピアの**テナントID**を確認できます。

!!! tip "ポイント"
    ピアプロジェクトにアクセス権限がない場合は、ピアプロジェクトの管理者からテナントIDを入手してください。

1. ピアプロジェクトのコンソール画面にアクセスします。
2. **Network > VPC > 管理**に移動します。
3. ピアリング対象または画面に表示されるVPCのいずれか1つを選択します。
4. **[基本情報] > テナントID**に表記されたID値をコピーします。

<a id="how-to-check-the-peer-id"></a>
### ピアIDの確認方法 { #how-to-check-the-peer-id }

次の手順で、ピアリングのピアIDを確認できます。

!!! tip "ポイント"
    ピアIDが表示されないピアリングは、従来の方法でポートを照会できます。

1. **Network > Peering Gateway > ピアリング**に移動します。
2. 対象のピアリングを選択します。
3. **[基本情報] > ピアID**に表記された値をコピーします。
