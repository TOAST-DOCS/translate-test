## Dev Tools > Pipeline > Stage Guide

This guide provides basic information about Pipeline stages.

You can add stages by clicking the **Edit Mode** toggle in the upper right of the Pipeline Studio screen to activate edit mode, then dragging and dropping stages revealed by clicking the tree menu in the **Add Stage** panel on the left.

You can view or edit detailed stage information in the **Stage Settings** panel on the right.

![stage-guide-01](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-01_new.png)

Stages are grouped into the following categories:

- **Source**
- **Build**
- **Deploy**
- **Function**

## Source

## Build
This is the stage for building.

### Build - Jenkins
You can build by using Jenkins that you configured. For **Build Tool**, you can choose a [build tool](/Dev%20Tools/Pipeline/en/environment-config/#_4) that you added in **Build Tool Settings** under **Environment Settings**. You can choose a **Build Job**.
You can configure the **Start Condition** and **End Condition** for **Artifacts**. You can configure the **Start Condition** to determine whether to start the stage. You can configure the **End Condition** to set the stage output as an artifact.

![stage-guide-04](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-04_new.png)

### Build - Bake(Manifest)
You can build by using a Helm package file that you configured or a [chart repository](/Dev%20Tools/Pipeline/en/environment-config/#_6).

- Chart name sets the name of the output built with the Helm engine.
- Namespace sets the namespace of the output built with the Helm engine.
- Template
    - For Repository Type, you can choose a repository that you added in [Source Repository Settings](/Dev%20Tools/Pipeline/en/environment-config/#_2) or [Chart Repository Settings](/Dev%20Tools/Pipeline/en/environment-config/#_6) under **Environment Settings**.
    - When you specify the repository type as **GitHub File** or **GitLab File**
        - For Path, you must enter the path to the Helm package file.
        - For Branch Name, enter the GitHub or GitLab branch.
    - When you specify the repository type as **Helm Chart**
        - For Chart Repository Name, you can choose one of the repositories that you configured in [Chart Repository Settings](/Dev%20Tools/Pipeline/en/environment-config/#_6).
        - For Chart Name, you can choose a chart name available in the chart repository configuration.
        - For Chart Version, you can choose a chart version available in the chart repository configuration.
- Override
    - Repository Information
        - You can choose in the same way as Template.
        - The build output is generated by replacing the content specified in Override based on the Template.
    - Key / Value
        - Enter values consisting of key and value pairs to generate build output by replacing specific values.
    - Replace Basic Type
        - When you select this option, --set is used instead of --set-string when injecting override values. Values injected using --set are converted to basic data types by Helm.
- Artifacts
    - You can configure the **Start Condition** and **End Condition** for **Artifacts**. You can configure the **Start Condition** to determine whether to start the stage. You can configure the **End Condition** to set the stage output as an artifact.

![stage-guide-05](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-10-29/stage-guide-05-1.png)

### Build - NHN Cloud Build Tools v2
You can use build tools provided by NHN Cloud.

- Build Environment Configuration
    - You can configure the performance and time limit of the build tool.
- Source Build Configuration
    - You can choose an [image repository](/Dev%20Tools/Pipeline/en/environment-config/#_3) that you added in **Image Repository Settings** under **Environment Settings**.
      - Enter the **Image Name** and **Tag** for the environment to build, and configure the **Build Command**.

- Docker Image Build Configuration
    - For **Dockerfile Path**, enter the path where the Dockerfile exists.
    - For **Dockerfile Execution Path**, enter the path to build the Dockerfile.
    - Choose the **Image Repository** and determine the **Image Name** to push the output to that repository.
    - For **Tag**, enter the tag for the image. When you enter including the tag format, the tag format part is dynamically substituted.

- Artifact Configuration
    - You can configure the **Start Condition** to determine whether to start the stage.
    - You can configure the **End Condition** to set the stage output as an artifact.


|Image Tag Format | Substituted Form | Description                                 |
| ----------- | ---------- |------------------------------------|
|{BUILD_DATE_TIME}| yyyy-MM-dd_HH_mm_ss| Substituted with the build execution time in the format year-month-day_hour_minute_second. |

## Deployment
This is the stage for deploying to a Kubernetes environment.

### Deployment - Deploy
- You can select a [deployment target](/Dev%20Tools/Pipeline/en/environment-config/#_5) that you added in **Deployment Target Settings** under **Environment Settings**.
Enter the **Stage Name**, **Deployment Target**, and **Manifest** to use for deployment.
If you used a tag format in the build stage, you can enter `_{BUILD_NUMBER}` for the Docker image tag part of the **Manifest** to deploy with the most recent numbered image from the images built with the tag format.
For information about how to write a **Manifest**, see the [Kubernetes documentation](https://kubernetes.io/docs/concepts/workloads/controllers/deployment ).
- You can select an artifact as the **Manifest Source**. The selected artifact must be created in Manifest format.
    - You can select an artifact created by the pipeline.
    - You can select a specific file from the repository as an artifact. 
- You can set **Start Conditions** and **End Conditions** for **Artifacts**. You can set **Start Conditions** to determine whether to start the stage. You can set **End Conditions** to set the stage output as an artifact.

![stage-guide-07](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-07_new.png)

### Deployment - Patch
- You can select a [deployment target](/Dev%20Tools/Pipeline/en/environment-config/#_5) that you added in **Deployment Target Settings** under **Environment Settings**.
- Enter the **Namespace**, **Resource Type**, **Selection Method**, **Resource Name**, and **Manifest** to use for deployment. You can use Patch to modify existing resource information.
- For information about how to write a **Manifest**, see the [Kubernetes documentation](https://kubernetes.io/docs/reference/kubectl/cheatsheet/#patching-resources).
- If you set **Selection Method** to **Select by Dynamic Method**, enter the **Cluster** and **Selection Strategy**.
- Cluster
    - For replicaSet, Pipeline deploys by specifying a version internally. If you choose **Select by Dynamic Method**, it selects targets according to the selection strategy rather than selecting a specific version.
- Selection Strategy
    - Newest: Selects the most recently deployed resource when the stage starts.
    - Second Newest: Selects the second most recently deployed resource when the stage starts.
    - Oldest: Selects the oldest resource when the stage starts.
    - Largest: Selects the resource with the most pods in the cluster when the stage starts.
    - Smallest: Selects the resource with the fewest pods in the cluster when the stage starts.

## Features
This is a stage that provides additional features.

### Features - Approval Management
Users with approval authority can manage **execution control (execution, stop execution)** for stages that follow the **Features - Approval Management** stage.

You can write request content for the stage, and the **execution control (execution, stop execution)** function of the approval management stage can only be performed by users with the **Pipeline APPROVAL ADMIN** role for that project.

![stage-guide-15](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-15_new.png)

The **Pipeline APPROVAL ADMIN** role can be granted in member management and role group management of the project.

![stage-guide-18](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2023-10-31/stage-guide-18.png)

### Features - Judgement (Execution Management)
You can enter **description** and **execution settings** for the execution management stage as needed.

You can perform **execution control (execution, stop execution)** for the next stage regardless of whether **execution settings** exist.
If you add **execution settings** and choose to execute the next stage, you can pass setting values to the Precondition (execution condition) stage described next to handle branch processing.

![stage-guide-16](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-16_new.png)

### Features - Precondition (Stage Status Condition)
You can set conditions by selecting the stage name and execution result from the previous step.
The next stage is executed only when all specified conditions are met.

![stage-guide-17](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-17_new.png)

### Features - Precondition (Execution Condition)
This determines the execution of subsequent stages based on the **execution condition** of the value received from the Judgement (execution management) stage set as the previous step.
The execution of subsequent stages is determined by selecting either **execution condition match/execution condition mismatch** for the setting value received from the Judgement (execution management) stage and the condition value of the **execution condition**.

![stage-guide-18](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-18_new.png)

### Features - Webhook
Enter the HTTP method and URL in **URL**. You can add **request headers** and **request data** as needed.
If the Webhook response value is one of the values entered in **Fail Fast HTTP Status Code**, the stage is immediately terminated.

![stage-guide-19](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-19_new.png)

### Features - Execute Other Pipeline
You can execute an entire other pipeline from the stage.
Select the **pipeline name** that you want to execute.

If you deselect **execution condition**, the next stage is executed without waiting for the execution status of the selected pipeline.

![stage-guide-20](https://kr1-api-object-storage.nhncloudservice.com/v1/AUTH_2acdfabf4efe4efc8a04c00b348110c9/cdn_origin/prod_pipeline/2024-08-27/pipeline-stage-guide/stage-guide-20_new.png)

### Features - Execute NHN Cloud Deploy Service Deployment
You can execute deployment using NHN Cloud Deploy service from the stage.
- If the **Command Type** of the artifact to execute deployment is **SSH**, the **Execute NHN Cloud Deploy Service Deployment** feature is not supported, and it is only supported when it is **Cloud Agent**. For related information, see [Deploy User Guide](/Dev%20Tools/Deploy/en/console-guide/#_8).

Select the security settings added in **Environment Settings** > **NHN Cloud Security Settings**, and enter the AppKey to use NHN Cloud Deploy service in **AppKey**.

After entering the information, choose **OK** to retrieve deployment-related information from NHN Cloud Deploy that matches the entered security settings and AppKey.

You can then select the **artifact**, **server group**, and **scenario** to deploy through NHN Cloud Deploy service.


Specify the execution completion wait time for the stage in **Deployment Timeout**. (minimum 1 minute, maximum 600 minutes)

In **Deployment Detail Settings**, you can add conditions for the deployment target.

In **Server Selection**, you can select servers to deploy. If you select **All Servers**, deployment proceeds targeting all servers, and if you choose **Select Servers**, you can select servers to deploy.

In **Concurrent Server Execution Count**, you can select how many servers NHN Cloud Deploy service will execute simultaneously. (default 1, maximum number of servers)

You can enter deployment execution information in **Deployment Notes**.

For detailed information, see [Deploy User Guide](/Dev%20Tools/Deploy/en/reference/#_1).

### Features - Provide User Variables

- Reference with pipeline expressions.

```
${myImage}
```

> When actually using, replace the variable name with the value specified in the stage. (e.g., `${buildTag}`, `${buildImage}`)

## Stage Common Features
### When a Stage Fails

You can choose settings related to pipeline execution when a stage fails.

- End entire pipeline
    - If the stage fails, the entire pipeline ends.
- End only this branch
    - Only the branch that contains the stage ends, and pipelines in other branches continue to run.
- End this branch and fail when other branches end
    - Only the branch that contains the stage ends, and pipelines in other branches continue to run. However, the result of the pipeline remains as failed.
- Ignore failure and continue
    - Even if the stage fails, the next stage proceeds.
