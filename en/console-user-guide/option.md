<a id="options"></a>
## Options { #options }

**Security > Network Firewall > Console User Guide > Options**

In the **Options** tab, you can set the options required for Network Firewall operation.

<br>

<a id="configure-logs"></a>
## Configure Logs { #configure-logs }

<a id="default-block-policy-log-settings"></a>
### Default Block Policy Log Settings { #default-block-policy-log-settings }

* Select whether to save the default block policy log that is mandatory created after Network Firewall is created.
    * When enabled, you can search logs created with the default blocking policy in the traffic log.

<a id="log-remote-transfer-setting"></a>
### Log Remote Transfer Setting { #log-remote-transfer-setting }

* Select the option to save traffic logs remotely.
    * Syslog: Send logs with up to 2 remote addresses
        * The 2 remote addresses can be configured individually (IP address, protocol, port number)
    * Object Storage: Send logs with the Object Storage service provided by NHN Cloud
    <img src="../../../static/images/24.11.07/OBS_5.png" height="65%" />
* Access key / Secret key: Enter the access key information available when registering S3 API credentials in the Object Storage service.
      * Bucket name: Enter the name of the container created in the Object Storage service.
      * Endpoint: Check the endpoint for each region and enter the endpoint that matches your location.
      * Region: Check the name for each region and enter the name that matches your region.
  * Log &amp; Crash Search: Sends logs to the Log &amp; Crash Search service provided by NHN Cloud.
  <img src="../../../static/images/24.11.07/LNCS_2.png" height="65%" />
      * AppKey: Enter the AppKey generated after activating the Log &amp; Crash Search service
  
!!! tip "Note"

    * When configuring Object Storage, refer to the [User Guide](/Storage/Object%20Storage/en/s3-api-guide/#aws-sdk) for input details.
    * When using the Log & Crash Search service, you can detect abnormal behavior by using the log alarm configuration feature.
    For example, add an ACL block policy in Network Firewall for SSH communication directed to a specific destination, then configure alarm conditions for logs generated by that policy. (e.g., 20 or more SSH connection attempt logs within 1 minute)
    When the conditions configured by the user are met, an alarm can be received.  

<br>

<a id="configure-general-settings"></a>
## Configure General Settings { #configure-general-settings }

<a id="mirroring-settings"></a>
### Mirroring Settings { #mirroring-settings }

* You can select whether to use the mirroring feature provided by Network Firewall.
    * When enabled, the subnet used to create Network Firewall is used as the required subnet.

<a id="configure-network-firewall"></a>
### Configure Network Firewall { #configure-network-firewall }

* You can configure Network Firewall as either single or redundant.

<a id="delete-network-firewall"></a>
### Delete Network Firewall { #delete-network-firewall }

* You can delete a Network Firewall that is in operation.
    * Network Firewall can be deleted separately in the Korea (Pangyo) region and the Korea (Pyeongchon) region.

!!! tip "Note"

    * The IP information of the mirroring interface required for ACL configuration can be found in **Network > Network Interface**.
        * Interface name: NetworkFirewall_INF_MIRRORING_S_NAT_VIP
    * Changing the configuration method may take a few minutes, and the service may be affected until the configuration change is complete.
    * It is recommended to perform Network Firewall change tasks such as policies and NAT after the configuration change is complete.

!!! danger "Caution"

    When deleting an operating Network Firewall, consider other services connected to Network Firewall before proceeding.  
    
<br>

<a id="disable-network-firewall-service"></a>
## Disable Network Firewall Service { #disable-network-firewall-service }

You can disable the Network Firewall service in **Project Management > Services in Use**.

!!! tip "Note"

    * Disabling the Network Firewall service applies to both the Korea (Pangyo) region and the Korea (Pyeongchon) region.
    For example, if the Network Firewall service is enabled in both the Korea (Pangyo) region and the Korea (Pyeongchon) region within the same project, it is not possible to disable the Network Firewall service in only one of the two regions.
    * To disable, delete Network Firewall in the Korea (Pangyo) region and the Korea (Pyeongchon) region separately before proceeding.
